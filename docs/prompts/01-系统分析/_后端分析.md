# 系统分析子模块 - 后端分析

> 适用范围：业务层后端代码（如 bladex-boot 的 `org.springblade` 业务包、ruoyi-admin、ruoyi-system）
>
> 由 `系统分析.md`（总控）按需引入，不独立使用。

---

## 本模块分析目标

聚焦业务层的**业务逻辑实现**，分析 Controller → Service → Mapper 的调用链、数据模型、事务控制、安全策略等。

---

## 1. 入口点分析

### 1.1 Web 入口
- 所有 `@RestController` / `@Controller`：类名、路径前缀（`@RequestMapping`）、包含的接口
- REST 接口：HTTP 方法、路径、入参、返回值类型
- 统一响应封装：`R<T>` / `AjaxResult` 等包装类的结构

### 1.2 非 Web 入口
- 定时任务：`@Scheduled`、Quartz 任务定义、任务类与执行逻辑
- 消息监听：消费者入口（`@RabbitListener`/`@KafkaListener`）、消息类型、消费幂等处理、重试/死信逻辑
- 事件监听：`@EventListener`、`@Async` 异步方法
- 外部回调：Webhook 接收、第三方回调处理

**输出格式**：
```
| 入口类型 | 类名 | 方法名 | 路径/触发条件 | 源文件路径 |
```

## 2. 调用链分析

### 2.1 Controller → Service → Mapper 链路
- 逐条追踪从 Controller 方法到 Mapper 的完整调用链
- 标注每层的类名、方法名、源文件路径
- 调用深度≥3层（Controller → Service 接口 → Service 实现 → Mapper）

### 2.2 Service 层分析
- 事务控制：`@Transactional` 标注位置、传播行为、回滚规则
- AOP 拦截：自定义切面、日志切面、权限切面
- 业务拆分：一个 Service 接口有多少实现类、拆分依据
- 跨 Service 调用：Service A 调用 Service B 的场景

### 2.3 Mapper / DAO 层分析
- MyBatis XML 映射：SQL 语句类型、动态 SQL（`<if>` / `<foreach>` / `<choose>`）
- MyBatis-Plus 特性使用：`IService`、`BaseMapper`、LambdaQueryWrapper
- PageHelper / 分页插件：分页实现方式
- 多数据源切换：`@DS` 注解使用、动态路由

### 2.4 调用链去重
- 若某 Service 接口有>3个实现类，仅深度分析3个典型实现
- CRUD 类接口可合并分析，复杂业务逻辑逐个分析

## 3. 数据模型分析

### 3.1 实体类
- 数据库表对应的实体类（Entity/DO）：类名、表名映射（`@TableName` / XML namespace）
- 字段映射：属性名 → 列名、类型转换
- 关联关系：一对多（`@OneToMany`）、多对一、多对多在代码中的表现

### 3.2 DTO / VO / Query 对象
- 数据传输对象：入参封装类、返回封装类
- 查询对象：分页查询条件封装
- 对象转换：Entity ↔ DTO 的转换方式（手动 / MapStruct / BeanUtils）

### 3.3 数据库表关系
- 外键关系（物理外键或逻辑外键）
- 关联表查询：JOIN 场景
- 软删除：`deleted` 字段的使用

---

## 4. 安全与权限分析

### 4.1 认证链路
- Token 验证流程：拦截器 → Token 解析 → 用户信息提取
- 登录流程：登录接口 → 凭证校验 → Token 生成
- 会话管理：Token 存储（Redis/内存）、过期策略、刷新机制

### 4.2 授权控制
- 接口级权限：`@PreAuthorize`、`@RequiresPermissions` 等注解
- 方法级权限：AOP 拦截中的权限校验
- 数据级权限：数据权限过滤（如部门数据隔离、个人数据隔离）
- 租户隔离：租户识别方式（Header/参数/域名/Token）、隔离策略（共享库共享表 vs 独立库）、`@TenantIgnore` 豁免场景、自动注入 `tenant_id` 的机制（AOP 切面/MyBatis 拦截器）

### 4.3 输入校验
- `@Validated` / `@Valid` 注解使用
- 自定义校验注解
- 参数清洗与过滤（XSS、SQL注入防护）

## 5. 国际化（可选）

- MessageSource：配置方式、fallback 策略
- 错误消息国际化：异常消息使用 i18n key 还是硬编码中文

## 6. 业务规则挖掘

**规则分类体系**：使用总控 `系统分析.md` 第 5 章统一的五分类定义，以下是针对后端分析的示例：

| 分类 | 本模块示例 |
|-----|----------|
| 计算规则 | 金额计算公式、税费计算 |
| 流程规则 | 审批流、订单状态机 |
| 约束规则 | 字段校验、唯一性、格式限制 |
| 权限规则 | 接口权限、数据隔离 |
| 异常规则 | 异常回滚、重试机制 |

### 6.1 提取方法

从代码中逆向提取业务规则，必须遵循以下提取路径：

**路径 A：校验规则提取**
```
注解/校验方法 → 校验逻辑 → 错误提示 → 归属规则
```
- 从 `@NotNull`、`@NotBlank`、`@Size`、`@Pattern` 等校验注解提取约束规则
- 从自定义校验注解（`@ValidXxx`）提取对应的 `ConstraintValidator` 实现逻辑
- 从方法内的手动校验（`if (xxx == null) throw`）提取隐式约束
- 从错误码/错误信息文件提取对应的用户提示

**路径 B：流程规则提取**
```
条件分支 → 业务含义 → 后续动作 → 状态变更
```
- 从 `if/switch` 条件分支提取业务决策点，标注每个分支的业务含义
- 从状态字段变更（如 `setStatus()`) 提取状态流转规则
- 从事件发布（`ApplicationEventPublisher`）提取触发-响应规则

**路径 C：计算规则提取**
```
字段运算 → 中间变量 → 最终结果 → 业务含义
```
- 从涉及数学运算、字符串拼接、日期计算的方法提取计算规则
- 从 DTO ↔ Entity 转换中的特殊处理提取字段映射规则
- 从数据库查询中的聚合函数（`SUM`、`COUNT`）提取统计规则

**路径 D：权限规则提取**
```
注解/拦截器 → 权限判断逻辑 → 拒绝策略 → 生效范围
```
- 从 `@PreAuthorize`、`@RequiresPermissions` 提取接口权限规则
- 从 AOP 切面中的权限校验提取方法级权限规则
- 从数据权限注解（如 `@DataScope`）提取数据过滤规则

**路径 E：异常规则提取**
```
try-catch → 异常处理策略 → 后续动作 → 用户反馈
```
- 从 `try-catch` 中的异常处理策略提取降级规则
- 从自定义异常类及其使用场景提取异常分类
- 从事务回滚配置（`@Transactional(rollbackFor = ...)`）提取回滚规则
- 从重试机制（如 `@Retryable`）提取重试策略

### 6.2 后端特有的隐式规则示例

- 条件分支中的业务决策（if/switch 中的业务含义）
- 未文档化的数据校验逻辑
- 隐式的数据转换或兼容性处理
- 状态机流转（如订单状态、审批状态）
- 通过方法命名暗示的业务规则（如 `isExpired()` 暗示有过期判断）

> 显式规则/隐式规则的通用定义见总控 `系统分析.md` 第 5 章。

### 6.3 规则依赖关系

提取规则之间的依赖关系，构建规则依赖图：

- 前置依赖：规则 B 的触发依赖规则 A 的通过（如"必须先登录才能触发审批"）
- 互斥关系：规则 A 和规则 B 不会同时生效
- 覆盖关系：规则 B 覆盖了规则 A 的行为（如某个特殊配置的优先级更高）
- 级联关系：规则 A 触发后自动触发规则 B

**隐藏业务规则清单输出格式**：
```
| 规则编号 | 规则描述 | 规则分类 | 显式/隐式 | 来源位置（类/方法/行） | 生效范围 | 依赖规则 | 是否有文档 |
|---------|---------|---------|----------|---------------------|---------|---------|-----------|
```
