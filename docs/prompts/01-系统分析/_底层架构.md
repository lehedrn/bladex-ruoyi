# 系统分析子模块 - 底层架构

> 适用范围：核心 tools、Starter 自动配置、基础设施层（如 blade-core-*、blade-starter-*、ruoyi-common、ruoyi-framework）
>
> 由 `系统分析.md`（总控）按需引入，不独立使用。

---

## 本模块分析目标

底层架构代码不直接处理业务，而是为业务层提供**基础能力**。分析重点不是"做什么业务"，而是"提供什么能力、如何被加载、如何被使用"。

---

## 1. 入口点分析

底层架构没有传统 Controller 入口，入口点在**自动装配机制**：

- **Spring Boot 自动装配**：`META-INF/spring.factories`、`META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports`、`@AutoConfiguration` 注解
- **Starter 依赖入口**：`pom.xml` 中的 starter 依赖声明（谁引入了这个 starter）
- **组件扫描**：`@ComponentScan` 配置、`@MapperScan` 扫描路径
- **配置类**：`@Configuration` 类、`@Bean` 方法定义
- **SPI 扩展**：如有 `META-INF/services/` 下的 SPI 文件，追踪接口-实现映射

**输出格式**：
```
| 入口类型 | 文件路径 | 触发的装配内容 | 被谁引入/依赖 |
```

## 2. 能力清单提取

Starter/工具库的核心价值是**对外提供的能力**，逐项提取：

### 2.1 自动装配能力
- 每个 `@Bean` 的定义：类名、方法名、条件注解（`@ConditionalOnXxx`）、返回类型
- 配置的默认值与可覆盖项：`@ConfigurationProperties` 对应的配置前缀和属性
- 条件装配链：`@ConditionalOnClass` → `@ConditionalOnMissingBean` → `@ConditionalOnProperty` 的完整链路

### 2.2 工具封装能力
- 工具类（`XxxUtil`）：封装了什么原生 API、简化了什么操作
- 封装类/包装类：统一了什么调用范式、隐藏了什么复杂度
- 自定义注解：注解名称、处理逻辑（AOP/拦截器）、生效范围

### 2.3 基础设施能力
- 数据源：动态切换机制、路由策略、读写分离实现
- 安全：认证过滤器链、Token 处理、权限解析
- 租户：租户解析 Filter、数据源路由策略、`TenantIgnore` 机制、租户隔离策略
- 缓存：缓存抽象、序列化策略、多数据源适配、分布式锁实现
- 消息队列：发送封装、消费幂等机制、重试/死信策略
- 日志/监控：切面拦截、指标采集、链路追踪

**输出格式**：
```
| 能力名称 | 提供类/配置 | 触发条件 | 配置属性 | 使用方（谁依赖了它） |
```

## 3. 依赖与调用关系分析

底层架构的调用方向与业务层**相反**——它是"被调用方"。

### 3.1 被使用方分析
- 扫描业务层（如 `bladex-boot` 的 `org.springblade` 业务代码、`ruoyi-admin`）中对本 starter 的引用
- 统计高频使用的工具类/方法
- 识别"声明了依赖但从未使用"的死引用

### 3.2 传递依赖分析
- starter 内部依赖了哪些第三方库（版本锁定在 BOM 中的 vs 自由声明的）
- 是否存在版本冲突风险
- 传递依赖链：starter → 第三方库 → 更底层依赖

### 3.3 模块间依赖图
- 各 starter 之间的依赖关系（A starter 依赖 B starter）
- 循环依赖检测

## 4. 配置体系分析

### 4.1 配置文件梳理
- 默认配置位置：`resources/` 下的 `.yml` / `.properties`
- 配置属性类：`@ConfigurationProperties` 标注的类及其属性
- 环境变量绑定：`${}` 占位符的使用与默认值

### 4.2 配置覆盖优先级
- 多层级配置的生效顺序：Starter 默认值 → application.yml → 环境变量 → 启动参数
- 多 profile 配置：`application-dev.yml`、`application-prod.yml` 等差异
- 条件配置：`@ConditionalOnProperty` 在不同配置值下的行为差异

## 5. 业务规则挖掘

**规则分类体系**：使用总控 `系统分析.md` 第 5 章统一的五分类定义，以下是针对底层架构的示例：

| 分类 | 本模块示例 |
|-----|----------|
| 计算规则 | 序列化策略、加密算法 |
| 流程规则 | Filter 链、拦截器链 |
| 约束规则 | 连接池上限、超时限制 |
| 权限规则 | 认证过滤器、Token 验证 |
| 异常规则 | 熔断、重试、降级 |

### 5.1 提取方法

**路径 A：配置驱动规则提取**
```
配置属性 → 默认值 → 可覆盖项 → 生效行为
```
- 从 `@ConfigurationProperties` 提取配置项及其对行为的影响
- 从 `@ConditionalOnProperty` 提取条件配置规则
- 从多 profile 配置（dev/prod）提取环境差异规则

**路径 B：装配条件规则提取**
```
条件注解 → 判断逻辑 → 装配结果 → 影响范围
```
- 从 `@ConditionalOnClass` 提取 classpath 依赖规则
- 从 `@ConditionalOnMissingBean` 提取 Bean 覆盖规则
- 从 `@AutoConfigureBefore/After` 提取装配顺序规则

**路径 C：拦截/过滤规则提取**
```
拦截器/Filter → 判断条件 → 拦截/放行 → 后续影响
```
- 从 Filter 链中的每个过滤器的判断逻辑提取拦截规则
- 从 AOP 切面中的切点表达式提取切面生效范围
- 从 HandlerInterceptor 的 `preHandle` 提取请求拦截规则

### 5.2 底层架构特有的隐式规则示例

- 自动装配的隐式条件（某个 class 不在 classpath 就跳过）
- 配置属性的隐式默认值
- Bean 创建的顺序依赖
- 隐式拦截行为（某个 Filter 在链中的位置导致特定行为）
- 配置覆盖的隐式优先级（环境变量 > yml > 默认值）
- 工具类的隐式约束（如某个工具方法对输入格式的要求）

> 显式规则/隐式规则的通用定义见总控 `系统分析.md` 第 5 章。

### 5.3 规则依赖关系

提取基础设施规则之间的依赖关系，以及对业务层规则的影响：

- 基础设施规则 A 是业务规则 B 的前提（如"必须先通过认证 Filter 才能进入业务 Controller"）
- 基础设施规则 A 覆盖了业务规则 B 的行为（如全局异常拦截器覆盖了 Controller 中的 try-catch）
- 多个 Filter/Interceptor 的执行顺序依赖

**隐藏业务规则清单输出格式**：
```
| 规则编号 | 规则描述 | 规则分类 | 显式/隐式 | 来源位置（类/方法/行） | 生效范围 | 影响业务规则 | 依赖规则 | 是否有文档 |
```

## 6. 设计模式识别

底层架构大量使用设计模式，必须识别并标注：

| 模式 | 典型场景 |
|------|---------|
| 工厂模式 | 对象创建、多实现选择 |
| 策略模式 | 多租户策略、数据源路由、序列化适配 |
| 模板方法 | 统一处理流程（如请求包装、响应封装） |
| 装饰器模式 | 拦截器链、Filter 包装 |
| 观察者模式 | 事件发布/监听（ApplicationEvent） |
| 单例模式 | 工具类、配置持有者 |

识别后标注具体代码位置：`类名 → 方法名 → 源文件路径`
