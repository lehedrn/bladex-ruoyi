# 系统分析子模块 - 前端分析

> 适用范围：前端应用（如 saber3、ruoyi-ui）
>
> 由 `系统分析.md`（总控）按需引入，不独立使用。

---

## 本模块分析目标

聚焦前端应用层的**组件架构、路由体系、状态管理、API 调用、交互流程**，分析前端如何组织 UI、管理数据、与后端交互。

---

## 1. 入口点分析

### 1.1 应用入口
- `main.ts` / `main.js`：应用初始化、插件注册、全局组件注册
- `App.vue`：根组件结构、路由出口（`<router-view>`）、全局布局

### 1.2 路由入口
- `router/index.ts`：路由表结构、路由懒加载配置
- 动态路由：后端返回菜单 → 前端动态注册路由的完整链路
- 路由守卫：全局前置守卫（`router.beforeEach`）、权限校验链

### 1.3 状态管理入口
- `store/index.ts`：Store 初始化、模块注册
- 各 Store 模块（user、permission、tagsView 等）：state/mutations/actions/getters

### 1.4 构建配置
- `vite.config.ts` / `vue.config.js`：代理配置、环境变量注入、插件配置
- `.env.*` 文件：环境区分、API 基础路径配置
- 分包策略：`rollupOptions` 中的 manualChunks 配置

### 1.5 国际化配置（可选）
- `vue-i18n` 初始化及版本
- Locale 文件：`src/locales/` 目录结构、支持的语言
- `$t()` 使用场景：组件中调用的 i18n key
- 语言切换：用户切换语言的入口、持久化策略

**输出格式**：
```
| 入口类型 | 文件路径 | 核心职责 | 初始化内容 |
```

## 2. 组件层级分析

### 2.1 组件树结构
- 根组件 → 布局组件（Layout） → 页面组件（Views） → 业务组件（Components）的嵌套关系
- 布局组件分析：侧边栏、头部、内容区、标签页等布局拆分
- 页面组件（`src/views/`）：按业务模块归类，每个页面组件的结构

### 2.2 组件复用
- 通用组件（`src/components/`）：表格组件、表单组件、弹窗组件、上传组件等
- 组件 Props 契约：Props 定义、类型、默认值、是否必填
- Emits 事件：子组件向父组件传递的事件
- 插槽（Slots）：组件内容定制点

### 2.3 组合式函数（Composables）
- `src/hooks/` 或 `src/composables/`：可复用逻辑封装
- 每个 hook 的输入参数、返回值、使用场景

### 2.4 指令与插件
- 自定义指令（`v-auth`、`v-hasPermi` 等权限指令）
- 全局注册的 Vue 插件
- 第三方 UI 库的封装适配（Element Plus、Avue 等）

---

## 3. 路由与权限分析

### 3.1 路由表结构
- 静态路由：固定路由（登录、404、首页等）
- 动态路由：从后端获取、权限过滤后注册的路由
- 路由嵌套：父子路由关系、布局嵌套

### 3.2 导航守卫链
- 全局前置守卫：执行顺序、每个守卫的判断逻辑
- 路由独享守卫：`beforeEnter` 配置
- 组件内守卫：`beforeRouteEnter`、`beforeRouteLeave`

### 3.3 权限控制
- 菜单权限：后端返回的菜单列表 → 路由表过滤
- 按钮权限：`v-hasPermi` 指令、权限码与后端接口的映射
- 数据权限：行级数据过滤（如只显示本部门数据）

---

## 4. 状态管理分析

### 4.1 Store 模块
- 每个模块的职责：user（用户信息）、permission（权限）、app（应用配置）、tagsView（标签页）等
- 模块间的依赖关系：哪些模块依赖其他模块的 state

### 4.2 状态变更链路
- Action 触发：用户操作 → dispatch action → commit mutation → state 变更 → 视图更新
- 持久化：哪些 state 持久化到 localStorage/sessionStorage
- 跨组件数据流：非父子组件如何通过 Store 通信

### 4.3 响应式数据
- `ref` / `reactive` 的使用场景
- `computed` 计算属性
- `watch` / `watchEffect` 监听器

---

## 5. API 调用层分析

### 5.1 请求封装
- HTTP 客户端实例化：`axios.create()` 配置
- 请求拦截器：Token 注入、请求签名、参数预处理
- 响应拦截器：错误码统一处理、Token 过期跳转、数据解包

### 5.2 API 模块化
- API 文件组织（`src/api/`）：按业务模块划分
- 每个 API 方法：请求路径、HTTP 方法、入参、返回值
- Mock 切换：开发环境 mock 与真实接口的切换机制

### 5.3 错误处理
- 全局错误拦截：网络错误、超时、服务器错误
- 业务错误：后端返回的错误码 → 前端提示映射
- 重试机制：是否有请求重试配置

## 6. 业务规则挖掘

**规则分类体系**：使用总控 `系统分析.md` 第 5 章统一的五分类定义，以下是针对前端分析的示例：

| 分类 | 本模块示例 |
|-----|----------|
| 计算规则 | 金额/税费前端计算、分页偏移量 |
| 流程规则 | 弹窗状态机、步骤条流转 |
| 约束规则 | 表单校验、格式限制 |
| 权限规则 | 按钮显隐、菜单过滤 |
| 异常规则 | 错误码映射、请求重试 |

### 6.1 提取方法

**路径 A：校验规则提取**
```
表单校验定义 → 校验逻辑 → 错误提示 → 归属规则
```
- 从 `rules` 对象、`el-form` 的 `:rules` 属性提取校验规则
- 从自定义校验函数（`validator: (rule, value, callback)`）提取复杂校验逻辑
- 从异步校验（远程验证、唯一性检查）提取服务端联动校验
- 从字段联动（watch 中触发其他字段变化）提取关联校验规则

**路径 B：流程规则提取**
```
交互触发 → 状态变更 → 后续动作 → 界面反馈
```
- 从弹窗/抽屉的打开-编辑-提交-关闭流程提取交互状态机
- 从列表页的加载→搜索→分页→排序→操作流程提取列表状态机
- 从步骤条（`el-steps`）的步骤流转提取向导流程规则
- 从路由跳转（`router.push/replace`）提取页面流转规则

**路径 C：计算规则提取**
```
数据转换函数 → 计算逻辑 → 显示结果
```
- 从数据格式化函数（日期、金额、数字格式）提取展示规则
- 从字典翻译（字典码 → 显示文本）提取映射规则
- 从树形数据转换（扁平 → 树形）提取结构转换规则
- 从 computed 属性中的计算逻辑提取前端计算规则

**路径 D：权限规则提取**
```
权限指令/判断 → 权限校验逻辑 → 隐藏/禁用策略
```
- 从 `v-hasPermi`、`v-auth` 等权限指令提取按钮级权限规则
- 从路由表中的 `meta.roles` / `meta.permissions` 提取页面权限规则
- 从菜单过滤逻辑（后端返回菜单 → 前端渲染过滤）提取菜单权限规则
- 从数据行级权限（操作列的条件渲染）提取数据权限规则

**路径 E：异常规则提取**
```
请求异常 → 拦截器处理 → 用户反馈 → 后续动作
```
- 从响应拦截器中的错误码处理提取错误映射规则
- 从网络错误/超时的处理策略提取降级规则
- 从请求重试配置（retry、axios-retry）提取重试策略
- 从 Token 过期的处理（跳转登录、刷新 Token）提取会话恢复规则

### 6.2 前端特有的隐式规则示例
- 条件渲染中的业务决策（`v-if` / `v-show` 中的判断条件业务含义）
- 未文档化的数据转换逻辑
- 通过组件命名或 Props 命名暗示的业务规则（如 `isEditable` 暗示可编辑判断）
- 路由守卫中的隐式跳转条件
- 状态管理的隐式依赖（某个 action 隐式依赖另一个模块的 state）

> 显式规则/隐式规则的通用定义见总控 `系统分析.md` 第 5 章。

### 6.3 规则依赖关系

提取前端规则之间的依赖关系，同时标注与后端规则的对应关系：

- 前端规则 A 依赖后端规则 B（如"前端校验通过后才发起请求"）
- 前端规则 A 与后端规则 B 共同约束同一业务点（双重校验）
- 前端规则 A 是后端规则 B 的前置过滤（前端快速拦截非法输入）

**隐藏业务规则清单输出格式**：
```
| 规则编号 | 规则描述 | 规则分类 | 显式/隐式 | 来源位置（组件/方法/行） | 生效范围 | 对应后端规则 | 依赖规则 | 是否有文档 |
```
