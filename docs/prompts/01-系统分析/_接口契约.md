# 系统分析子模块 - 接口契约

> 适用范围：前后端分离项目的接口对齐
>
> 由 `系统分析.md`（总控）按需引入，仅在项目同时包含前后端时启用。
>
> 本模块**消费** `_后端分析.md` 和 `_前端分析.md` 的接口信息，做一致性校验。

**执行模式说明**：

- **模式 B（Agent Teams）**：从 Phase 1 Agent 的输出文件 `后端-分析报告.md` 和 `前端-分析报告.md` 中读取接口信息
- **模式 A（单线程）**：总控已先完成前后端各自分析，直接从分析结果中提取接口信息；如分析报告尚未生成，则直接从源码提取前后端接口定义后执行本章

---

## 本模块分析目标

对比前后端接口定义与调用的差异，输出**接口一致性报告**，确保前后端联调无遗漏。

---

## 1. 后端接口提取

**模式 B（Agent Teams）**：直接从 `后端-分析报告.md` 的"后端接口清单"章节读取。
**模式 A（单线程）**：从总控前后端分析结果中提取，或直接从源码提取。

### 1.1 接口清单
- 每个 Controller 接口：HTTP 方法、路径、入参类型、返回值类型
- 接口分组：按 Controller 或业务模块归类
- 接口状态：正常/废弃/仅内部调用

### 1.2 参数规范
- 入参结构：Query 参数、Path 参数、Body 参数
- 参数校验：`@NotNull`、`@NotBlank`、`@Size` 等校验注解
- 分页参数：统一的分页请求格式

### 1.3 响应规范
- 统一响应体结构：`{code, msg, data}` 或类似封装
- 分页响应结构：`{total, records}` 等
- 错误响应：不同 HTTP 状态码对应的响应格式

**输出格式**：
```
| 接口路径 | HTTP方法 | 所属模块 | Controller类 | 入参类型 | 返回值类型 | 源文件路径 |
```

---

## 2. 前端 API 调用提取

**模式 B（Agent Teams）**：直接从 `前端-分析报告.md` 的"前端 API 调用清单"章节读取。
**模式 A（单线程）**：从总控前后端分析结果中提取，或直接从源码提取。

### 2.1 API 调用清单
- 前端定义的每个 API 方法：请求路径、HTTP 方法、入参、返回值
- API 文件归属：`src/api/` 下的哪个模块文件

### 2.2 调用关系
- 哪些组件调用了这个 API：`src/views/` 下的哪个页面
- 调用时机：页面加载、按钮点击、表单提交等

### 2.3 请求拦截器影响
- 请求拦截器自动注入的内容：Token、租户ID等
- 响应拦截器自动处理的内容：错误码统一处理、数据解包

**输出格式**：
```
| API路径 | HTTP方法 | 所属模块 | 调用组件 | 源文件路径 |
```

## 3. 前后端接口对齐

### 3.1 完全匹配
- 后端有且前端有调用：路径和方法完全一致的接口
- 标注：接口路径、参数对齐情况、响应结构对齐情况

### 3.2 后端有但前端未调用
- 后端定义了接口，但前端没有任何组件调用
- 可能原因：未开发完成、废弃接口、仅后端内部调用
- 需要确认：是遗漏还是有意不实现

### 3.3 前端有调用但后端无对应
- 前端定义了 API 方法，但后端没有匹配的 Controller
- 可能原因：后端未实现、接口路径不一致（前端写错）、动态接口
- 需要确认：是路径拼写错误还是后端缺失

### 3.4 接口路径不一致但功能匹配
- 前后端路径不同但实际指向同一功能（如代理配置做了路径重写）
- 需要通过 `vite.config.ts` 的 proxy 配置、Nginx 配置等确认映射关系

**差异清单输出格式**：
```
| 对齐状态 | 后端接口 | 前端API | 差异说明 | 需确认事项 |
|----------|---------|---------|---------|-----------|
| ✅ 匹配  | GET /api/user/list | GET /api/user/list | - | - |
| ⚠️ 后端有 | POST /api/user/export | 无调用 | 前端未接入 | 是否需要？ |
| ❌ 前端有 | 无对应 | GET /api/user/profile/v2 | 后端未实现 | 版本不一致？ |
| ⚠️ 路径不同 | GET /api/system/dict | GET /api/dict/list | 代理重写 | 确认proxy配置 |
```

## 4. 数据结构对齐

### 4.1 入参对齐
- 前端传的字段 vs 后端接收的字段
- 字段名是否一致（驼峰 vs 下划线）
- 字段类型是否一致（字符串传数字、布尔传字符串）
- 必填字段：前端校验 vs 后端 `@NotNull` 是否一致

### 4.2 出参对齐
- 后端返回的字段 vs 前端期望的字段
- 前端多用了后端没返回的字段（运行时 undefined）
- 后端返回了前端没使用的字段（冗余）
- 嵌套结构：对象嵌套的层级是否一致

### 4.3 分页结构对齐
- 前端传的分页参数（pageNo/pageSize）vs 后端接收的参数名
- 后端返回的分页结构（total/records）vs 前端解析的字段名

---

## 5. 错误码与状态码对齐

### 5.1 错误码体系
- 后端定义的错误码清单
- 前端错误码映射（响应拦截器中的错误码处理）
- 前端是否处理了所有后端可能返回的错误码
- 错误消息多语言：后端错误码 → 前端各语言消息文件的映射是否完整

### 5.2 HTTP 状态码
- 后端返回的 HTTP 状态码（200/401/403/500）
- 前端是否对不同状态码做了差异化处理

### 5.3 国际化消息对齐（如项目有 i18n）
- 后端错误码/错误消息 key vs 前端 locale 文件中的翻译 key 是否一致
- 后端新增的错误码，前端各语言文件是否都有对应翻译
- 前端硬编码的提示文字 vs 后端 i18n key 是否重复（应统一使用后端 key）

## 6. 业务规则对齐

### 6.1 约束规则对齐

对比前后端对同一数据的校验规则是否一致：

| 对比维度 | 后端实现 | 前端实现 | 差异说明 |
|---------|---------|---------|---------|
| 必填校验 | `@NotNull` 的字段 | 表单 `required: true` | 是否一致 |
| 长度校验 | `@Size(min, max)` | 表单 `min/max` | 数值是否一致 |
| 格式校验 | `@Pattern(regexp)` | 表单正则/自定义 validator | 规则是否一致 |
| 范围校验 | `@Min/@Max` | 表单 `min/max` | 数值是否一致 |
| 自定义校验 | `@ValidXxx` 的 Validator | 自定义 validator 函数 | 逻辑是否一致 |

**重点关注**：
- 前端校验比后端宽松（前端允许的值后端会拒绝）
- 前端校验比后端严格（前端拦截了合法值）
- 后端有校验但前端无（需要网络请求才知道是否合法）
- 前端有校验但后端无（前端拦截的值后端实际允许）

### 6.2 权限规则对齐

| 对比维度 | 后端实现 | 前端实现 | 差异说明 |
|---------|---------|---------|---------|
| 接口权限 | `@PreAuthorize` 表达式 | `v-hasPermi` 指令 | 权限码是否一致 |
| 数据权限 | `@DataScope` 过滤 | 前端数据过滤 | 过滤条件是否一致 |
| 菜单权限 | 后端返回菜单列表 | 前端渲染过滤 | 是否完全对应 |

### 6.3 流程规则对齐

| 对比维度 | 后端实现 | 前端实现 | 差异说明 |
|---------|---------|---------|---------|
| 状态流转 | Service 层状态变更 | 前端交互状态机 | 状态是否一致 |
| 异常处理 | 后端异常/回滚 | 前端错误处理 | 错误反馈是否匹配 |
| 重试机制 | 后端重试 | 前端重试 | 次数/策略是否一致 |

### 6.4 计算规则对齐

| 对比维度 | 后端实现 | 前端实现 | 差异说明 |
|---------|---------|---------|---------|
| 数值计算 | Service 层计算逻辑 | 前端 computed/方法 | 计算结果是否一致 |
| 数据格式化 | 后端格式化 | 前端过滤器/管道 | 显示格式是否一致 |
| 字典翻译 | 后端字典服务 | 前端字典缓存 | 翻译结果是否一致 |

**业务规则对齐输出格式**：
```
| 规则编号 | 规则描述 | 规则分类 | 后端规则编号 | 前端规则编号 | 后端显式/隐式 | 前端显式/隐式 | 对齐状态 | 差异说明 |
|---------|---------|---------|-------------|-------------|-------------|-------------|---------|---------|
| CT-001 | 用户名长度限制 | 约束规则 | BE-001 | FE-001 | 显式 | 显式 | ✅ 一致 | 均为 2-20 字符 |
| CT-002 | 金额计算精度 | 计算规则 | BE-005 | FE-003 | 显式 | 隐式 | ⚠️ 不一致 | 后端 BigDecimal，前端 Number 精度丢失 |
```

## 8. 输出文档结构

本模块的分析产出作为 `07_接口契约文档.md` 的核心内容来源。总控汇总时仅做格式规范化，不改变内容。

**差异清单是核心产出**，必须明确标注：
- `✅` 完全匹配的接口数量和业务规则
- `⚠️` 需要确认的接口（后端有但前端未调用、路径不一致等）
- `❌` 缺失的接口（前端调用了但后端无对应、后端实现了但前端未接入）
