**主要差异（共 26 项）：**

1. **D-01 后端缺失 `/logout` 接口**：前端 `login.js` 调用 `POST /logout`，但后端无任何 Controller 处理该方法。RuoYi 采用 JWT + Redis 架构，前端退出时仅清除本地 Token。

2. **D-13 孤立权限标识 `monitor:operlog:query`**：前端操作日志页面的"详细"按钮使用此权限，但后端 `SysOperlogController` 中没有对应 `@PreAuthorize` 注解。该按钮仅对拥有 `*:*:*` 全通权限的用户可见。

3. **D-10/D-11 批量删除参数不匹配**：后端 DELETE 接口设计为 `Long[]` 批量删除（如 `/system/notice/{noticeIds}`），前端 API 函数仅传递单个 ID。功能可用但未充分利用后端能力。

4. **D-17 唯一性校验仅在后端**：角色名称、菜单名称、部门名称等的唯一性检查全部仅在后端实现，前端无异步预校验，用户体验上需提交后才知冲突。

5. **D-12 Content-Type 头不严谨**：`uploadAvatar()` 显式设置 `application/x-www-form-urlencoded`，但实际传递 FormData，axios 会自动覆盖。
