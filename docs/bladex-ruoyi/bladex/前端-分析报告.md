## 第1章：入口点分析

### 1.1 入口点概览

| 入口类型 | 文件路径 | 核心职责 | 初始化内容 |
|---------|---------|---------|-----------|

## 第3章：路由与权限分析

### 3.1 路由表结构

### 3.3 动态路由机制

**完整链路**：

```
1. 用户登录成功
   ↓
2. store.dispatch('GetMenu', topMenuId)
   ↓ (调用 /blade-system/menu/routes)
3. 后端返回菜单树数据
   ↓
4. formatPath(ele, true) 处理每个菜单节点
   - 设置 icon 默认值
   - 设置 meta.keepAlive = (isOpen === 2)
   - 非子节点：component = 'views' + path
   - URL 类型：component = 'components/iframe/main'，注入 query.url
   ↓
5. commit('SET_MENU', menu) / commit('SET_MENU_ALL', menu)
   - 持久化到 localStorage
   ↓
6. store.dispatch('GetButtons')
   - 调用 /blade-system/menu/buttons 获取按钮权限
   - commit('SET_PERMISSION') 递归提取所有 code
   ↓
7. router.$avueRouter.formatRoutes(data, true)
   - 递归遍历菜单树
   - 使用 import.meta.glob 动态加载组件
   - 处理 iframe 场景（URL 路径转换为 /iframe/{id}）
   - router.addRoute() 逐个注册
```

**动态路由注册核心逻辑**（`avue-router.js` formatRoutes）：

- 首层路由（`first=true`）：使用 `page/index/layout.vue` 或 `page/index/index.vue` 作为父组件
- 嵌套路由（`isChild && !first`）：使用 `page/index/layout.vue` 作为父组件
- 叶子节点：通过 `modules[`../${component}.vue`]` 动态加载
- iframe 路由：自动设置 component 为 `components/iframe/main`

**【异常/幻觉警告区】**：`router/index.js` 第 20 行 `Router.$avueRouter.formatRoutes(Store.getters.menuAll, true)` 在应用启动时立即执行，但此时 menuAll 可能为空（从 localStorage 恢复）。这意味着冷启动时动态路由可能未正确注册，需要依赖 `page/index/index.vue` 的 `openMenu()` 方法重新加载。

### 3.4 导航守卫链

`permission.js` 中的 `router.beforeEach` 执行链：

```
router.beforeEach(to, from, next)
├── 1. 设置懒加载组件的 name = to.fullPath（用于 keep-alive）
├── 2. 判断是否来自菜单点击（isMenu 标志）
├── 3. 检查 getToken() 是否存在
│   ├── 有 Token：
│   │   ├── 3a. 锁屏检查：isLock 且非锁屏页 → 跳转 /lock
│   │   ├── 3b. 已登录访问 /login → 跳转 /
│   │   └── 3c. 正常导航：
│   │       ├── token 为空 → FedLogOut → 跳转 /login
│   │       ├── meta.target → window.open 打开外部链接
│   │       ├── meta.isTab !== false → ADD_TAG（添加标签页）
│   │       └── next() 放行
│   └── 无 Token：
│       ├── meta.isAuth === false → next() 放行
│       └── 否则 → next('/login') 跳转登录
│
router.afterEach(to)
├── NProgress.done()
├── 生成并设置页面标题（AvueRouter.setTitle）
└── SET_IS_SEARCH(false)
```

### 3.5 权限控制体系

#### 3.5.1 菜单权限

- **来源**：后端 `/blade-system/menu/routes` 接口返回菜单树
- **过滤**：前端通过 `formatPath` 处理，不符合条件的路由（URL 且非 iframe）被排除
- **注册**：`formatRoutes` 递归处理并 `addRoute` 动态注册

#### 3.5.2 按钮权限

- **来源**：后端 `/blade-system/menu/buttons` 接口返回按钮权限树
- **处理**：`SET_PERMISSION` mutation 递归提取所有叶子节点的 `code`，构建 `{ code: true }` 对象
- **存储**：持久化到 `sessionStorage`
- **使用**：页面中通过 `v-if="permission.xxx_yyy"` 控制按钮显隐

**示例**（user.vue 第 37 行）：
```html
<el-button v-if="permission.user_add && !auditMode" ...>新增</el-button>
```

#### 3.5.3 行级权限

- Avue CRUD 通过 `:permission` 属性传入 `permissionList` computed
- 映射关系：`{ addBtn: permission.user_add, viewBtn: false, delBtn: false, editBtn: false }`

#### 3.5.4 角色权限

- 部分操作需要 `userInfo.authority.includes('admin')` 判断
- 如：审核、设置主管、平台配置、账号解封、导入导出

## 第4章：状态管理分析

### 4.1 Store 模块概览

Vuex Store 包含 5 个模块：

| 模块 | 路径 | 职责 | 持久化 |
|------|------|------|--------|
| user | `store/modules/user.js` | 用户认证、菜单、权限、角色 | localStorage: token, refreshToken, tenantId, userInfo, menu, menuAll; sessionStorage: permission |
| common | `store/modules/common.js` | 语言、侧边栏状态、全屏、锁屏、主题 | localStorage: language, colorName, themeName; sessionStorage: isLock, lockPasswd |
| tags | `store/modules/tags.js` | 标签页导航（tagList、当前 tag、欢迎 tag） | localStorage: tagList, tag |
| logs | `store/modules/logs.js` | 前端错误日志收集与上报 | localStorage: logsList |
| dict | `store/modules/dict.js` | 数据字典、流程路由配置 | localStorage: flowRoutes |

### 4.2 User 模块详情

**State**：
```javascript
{
  tenantId: '',        // 租户ID
  userInfo: {},        // 用户信息（包含 userId, userName, deptId, roleId, roleName, avatar 等）
  permission: {},      // 按钮权限 { code: true }
  roles: [],           // 用户角色列表
  menuId: {},          // 当前选中菜单ID
  menu: [],            // 当前菜单树
  menuAll: [],         // 全部菜单树（累加模式）
  token: '',           // 访问令牌
  refreshToken: ''     // 刷新令牌
}
```

**Actions**：
| Action | 说明 | 调用 API |
|--------|------|---------|
| LoginByUsername | 用户名密码登录 | loginByUsername (SM2 加密密码) |
| LoginBySocial | 第三方社交登录 | loginBySocial |
| LoginBySso | 单点登录 | loginBySso |
| LoginByPhone | 手机验证码登录 | loginByPhone (SM2 加密手机号) |
| RegisterUser | 用户注册 | registerUser (SM2 加密密码) |
| GetUserInfo | 获取用户信息 | getUserInfo |
| RefreshToken | 刷新 Token | refreshToken |
| LogOut | 登出（调用后端 logout 接口） | logout |
| FedLogOut | 前端登出（不调用后端） | - |
| GetTopMenu | 获取顶级菜单 | getTopMenu |
| GetMenu | 获取菜单树 + 按钮权限 | getRoutes + getButtons |
| GetButtons | 获取按钮权限 | getButtons |

**关键变更链路**：
```
LoginByUsername → SET_TOKEN → setToken(Cookie) → localStorage
                → SET_REFRESH_TOKEN → setRefreshToken(Cookie) → localStorage
                → SET_TENANT_ID → localStorage
                → SET_USER_INFO → localStorage
                → DEL_ALL_TAG → 清空标签页
                → CLEAR_LOCK → 清除锁屏状态
```

### 4.3 Common 模块详情

**State**：

### 4.4 Tags 模块详情

**Mutations**：
| Mutation | 说明 |
|----------|------|
| ADD_TAG | 添加标签页（去重判断 fullPath），持久化 |
| DEL_TAG | 删除指定标签页 |
| DEL_ALL_TAG | 删除所有标签页（可保留部分） |

### 4.5 持久化策略

| 存储类型 | Key 前缀 | 存储项 |
|---------|---------|--------|
| localStorage | `saber3-` | token, refreshToken, tenantId, userInfo, menu, menuAll, language, colorName, themeName, tagList, tag, logsList, flowRoutes |
| sessionStorage | `saber3-` | permission, isLock, lockPasswd |
| Cookie | `saber3-access-token` | Token |
| Cookie | `saber3-refresh-token` | RefreshToken |
| Cookie | `JSESSIONID` | 会话ID |
| Cookie | `b-user-id` | 用户ID |

**Store 工具**（`utils/store.js`）：
- `setStore({ name, content, type })`：`type` 为 'session' 存 sessionStorage，否则存 localStorage
- `getStore({ name, debug })`：先查 sessionStorage，再查 localStorage
- Key 自动添加前缀：`website.key + '-'` = `'saber3-'`

| 6 | Token 注入：`Blade-Auth: bearer {token}` 或 `crypto {加密token}` | L63-74 |

**可配置项**（通过 config 属性控制）：
- `config.authorization = false`：不发送 Basic 认证头
- `config.meta.isToken = false`：不发送 Token
- `config.cryptoToken = true`：Token 使用 AES 加密
- `config.cryptoData = true`：请求/响应数据使用 AES 加密
- `config.meta.isSerialize = true`：POST 数据序列化为 form 格式

### 5.3 响应拦截器

| 状态码 | 处理逻辑 | 代码行 |
|--------|---------|--------|
| 白名单状态码 | 直接 reject，由调用方处理 | L117 |
| 401 (首次) | 触发 Token 刷新机制，重试原请求 | L120-177 |
| 401 (已重试) | 清除 Token，跳转登录页 | L181-193 |
| >2000 (OAuth2 错误) | 显示 error_description，reject | L196-205 |
| !=200 (一般错误) | ElMessage 错误提示，reject | L208-214 |
| 200 | 正常返回响应 | L215 |
| 网络错误 | NProgress.done(), reject | L217-220 |

**Token 刷新机制**（FE-019）：
```
401 响应 → 检查 config._retry
├── 未重试过：
│   ├── 设置 _retry = true
│   ├── 检查 isRefreshing（是否已在刷新）
│   │   ├── 正在刷新：等待 refreshTokenPromise 完成，重发请求
│   │   └── 未刷新：开始刷新
│   │       ├── isRefreshing = true
│   │       ├── store.dispatch('RefreshToken')
│   │       │   ├── 成功：重置 isRefreshing，更新 Token，重发原请求
│   │       │   └── 失败：重置 isRefreshing，清除 Token，跳转登录
│   │       └── 返回 refreshTokenPromise
│   └── 已重试过：清除 Token，跳转登录
```
