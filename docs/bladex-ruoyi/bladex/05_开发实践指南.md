## 第2章：后端最佳实践

### 2.1 事务控制

| 实践 | 说明 | 来源 |
|------|------|------|
| `@Transactional(rollbackFor = Exception.class)` | 所有写操作方法都标注此注解，确保异常时回滚 | 后端报告 2.2 |
| 默认传播行为（REQUIRED） | 未显式指定传播行为，使用 Spring 默认 | 后端报告 2.2 |
| 涉及多表操作的方法必须使用事务 | 如 grant() 涉及角色-菜单-数据权限-接口权限四张表 | 后端报告 2.1 |

**需要事务的方法**：
- `UserServiceImpl.submit()` — 用户新增 + 部门关联
- `UserServiceImpl.updateUser()` — 用户修改
- `UserServiceImpl.removeUser()` — 用户删除（多表联动）
- `UserServiceImpl.importUser()` — Excel 导入
- `UserServiceImpl.registerGuest()` — 第三方注册
- `RoleServiceImpl.grant()` — 角色权限授予

### 2.2 权限模式

| 模式 | 注解 | 使用场景 | 来源 |
|------|------|---------|------|
| `@IsAdmin` | 需要登录即可 | 大部分业务接口 | 后端报告 4.2 |
| `@IsAdministrator` | 需要超级管理员角色 | 租户管理、系统配置、代码生成 | 后端报告 4.2 |
| `@PreAuth(menu = "xxx")` | 需要指定菜单权限 | 部门、字典、岗位、通知等 | 后端报告 4.2 |
| `@PreAuth(PERMIT_ALL)` | 允许所有人访问 | 下拉数据源接口 | 后端报告 4.2 |
| `@NonDS` | 非租户数据源 | 90%+ 的 Controller | 后端报告 4.3 |

### 2.3 数据权限

| 层级 | 实现方式 | 来源 |
|------|---------|------|
| SQL 级 | `TenantLineInnerInterceptor` 自动追加 WHERE tenant_id = ? | 底层架构报告 |
| 数据源级 | `@TenantDS` / `@NonDS` 注解切换数据源 | 底层架构报告 |
| 数据范围级 | `@DataAuth` + `DataScopeInterceptor` 在 SQL 追加 WHERE | 底层架构报告 AR-028 |
| 手动级 | 查询时手动添加 `.eq(Entity::getTenantId, bladeUser.getTenantId())` | 后端报告 4.3 |

### 2.4 Wrapper 转换

统一使用 `XxxWrapper` 类进行 Entity → VO 转换，继承 `BaseWrapper`：

```
Entity → XxxWrapper.build().entityVO(entity) → VO
IPage<Entity> → XxxWrapper.build().pageVO(pages) → IPage<VO>
```

### 2.5 缓存管理

| 实践 | 说明 | 来源 |
|------|------|------|
| `CacheUtil.clear(USER_CACHE)` | 用户操作后清除用户缓存 | 后端报告 2.1 |
| `CacheUtil.clear(SYS_CACHE)` | 租户/系统操作后清除系统缓存 | 后端报告 BE-028 |
| `@Cacheable` | 路由权限信息缓存（MENU_CACHE） | 后端报告 BE-040 |

## 第3章：前端最佳实践

### 3.1 组件复用

## 第4章：常见陷阱

### 4.1 架构级陷阱

| 陷阱 | 描述 | 规避方案 | 来源 |
|------|------|---------|------|
| 冷启动路由失效 | `router/index.js` 第 20 行在 menuAll 为空时立即执行 formatRoutes | 依赖 `page/index/index.vue` 的 `openMenu()` 重新加载 | 前端报告【异常/幻觉警告区】 |
| .env 文件位置不确定 | 环境变量通过 loadEnv 从项目根目录加载，非 src/ 下 | 确认 .env 文件在 saber3/ 根目录 | 前端报告【异常/幻觉警告区】 |
| 部分模块代码量极少 | flowable/develop/http/log4j2/test 模块缺少独立配置类 | 使用时需参考原生文档 | 底层架构报告【异常/幻觉警告区】 |

### 4.2 后端陷阱

| 陷阱 | 描述 | 规避方案 | 来源 |
|------|------|---------|------|
| 用户删除自身 | 后端强制校验不可删除自身（BE-006），前端需处理此异常 | 调用 removeUser 前检查当前用户 | 后端报告 BE-006 |
| 用户修改信息字段忽略 | `updateUserInfo()` 强制忽略 role/dept/post/account/leaderId 字段（BE-008） | 前端需确认是否依赖此行为 | 后端报告 BE-008 |
| 国际化缺失 | 后端所有错误消息均为硬编码中文（BE-xxx） | 暂无 i18n 基础设施，需注意 | 后端报告 5.1 |
| Controller 无权限保护 | WorkController、SearchController、LeaveController 无权限注解 | 需确认是否为有意设计 | 后端报告 4.2 |
| 无权限保护 | 部分 Controller 无权限注解 | 需确认是否为有意设计 | 后端报告 4.2 |
| SMS 端点路径不一致 | 前端调用 `/blade-auth/oauth/sms/send-validate`，后端定义 `/oauth/sms/send-validate` | 需确认代理配置 | 接口契约报告 3.4 |

### 4.3 前端陷阱

| 陷阱 | 描述 | 规避方案 | 来源 |
|------|------|---------|------|
| 宽松状态码校验 | `validateStatus` 接受 200-500 为有效响应，可能掩盖服务端错误 | 建议收紧范围或显式处理 4xx/5xx | 前端报告 FE-015 |
| 响应不解包 | 响应拦截器不自动解包 R<T>，需手动访问 `response.data.data` | 调用时注意嵌套层级 | 接口契约报告 4.1 |
| 脱敏字段提交 | 用户更新时 phone/email 仅提交已修改的值 | 需理解后端忽略未提交字段的逻辑 | 前端报告 FE-035 |
| DevTools 检测 | 开发环境检测 DevTools 打开时 5 秒后关闭页面 | 调试时注意关闭检测或使用断点绕过 | 前端报告 FE-050 |
| 蛇形/驼峰映射 | 后端返回 snake_case，前端需手动映射为 camelCase | 映射逻辑在 store/modules/user.js:314-335 | 接口契约报告 4.4.2 |

### 4.4 接口陷阱

| 陷阱 | 描述 | 规避方案 | 来源 |
|------|------|---------|------|
| 后端有前端未调用的接口 | 29 个后端接口前端未使用（如 import-user、export-template、routes-ext 等） | 需确认是否为预留接口或废弃功能 | 接口契约报告 3.2 |
| 角色 API 跨模块调用 | 角色管理调用 menu 模块的 grant-tree 和 role-tree-keys | 需理解跨模块依赖关系 | 接口契约报告 3.1.4 |
| sendLogs 复用 logout 路径 | FE-A12 sendLogs 复用 logout POST 路径进行日志上报 | 容易混淆，建议分离 | 接口契约报告 3.2 BE-029 |
