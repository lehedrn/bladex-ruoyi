## 1. 设计模式应用

### 1.1 策略模式 — TokenGranter

**核心思想**: 将不同的登录方式（密码登录、验证码登录、短信登录、社交登录等）抽象为统一的策略接口，通过工厂类按需获取。

**接口定义**:

```java
// 源码: bladex-tool/blade-core-auth/blade-core-oauth2/src/main/java/org/springblade/core/oauth2/granter/TokenGranter.java
public interface TokenGranter {
    String type();                                    // 返回授权类型标识
    OAuth2Client client(OAuth2Request request);       // 获取客户端信息
    OAuth2User user(OAuth2Request request);           // 获取用户信息
    OAuth2Token token(OAuth2User user, OAuth2Request request); // 创建令牌
    void enhancer(TokenGranterEnhancer enhancer);     // 自定义增强
}
```

**已内置的 Granter 实现**:

| 实现类 | grantType | 说明 | 源码位置 |
|--------|-----------|------|----------|
| `PasswordTokenGranter` | `password` | 账号密码登录 | `.../granter/PasswordTokenGranter.java` |
| `RefreshTokenGranter` | `refresh_token` | 刷新 Token | `.../granter/RefreshTokenGranter.java` |
| `AuthorizationCodeGranter` | `authorization_code` | 授权码模式 | `.../granter/AuthorizationCodeGranter.java` |
| `ClientCredentialsGranter` | `client_credentials` | 客户端凭证 | `.../granter/ClientCredentialsGranter.java` |
| `ImplicitGranter` | `implicit` | 简化模式 | `.../granter/ImplicitGranter.java` |
| `CaptchaTokenGranter` | `captcha` | 验证码登录 | bladex-boot 业务代码中 |
| `SmsCodeTokenGranter` | `sms_code` | 短信验证码登录 | bladex-boot 业务代码中 |
| `SocialTokenGranter` | `social` | 第三方社交登录 | bladex-boot 业务代码中 |
| `RegisterTokenGranter` | `register` | 注册模式 | bladex-boot 业务代码中 |

**工厂类**: `TokenGranterFactory` 通过 `type()` 匹配并使用 `ConcurrentHashMap` 缓存实例。

```java
// 源码: bladex-tool/blade-core-auth/blade-core-oauth2/src/main/java/org/springblade/core/oauth2/granter/TokenGranterFactory.java
public TokenGranter create(String grantType) {
    return GRANTER_POOL.computeIfAbsent(grantType, this::initializeTokenGranter);
}
```

### 1.2 规则链模式 — OSS / SMS

**核心思想**: 通过接口定义规则，实现类根据租户/业务配置动态选择底层服务提供商。

**OSS 规则**:

```java
// 源码: bladex-tool/blade-starter-oss/src/main/java/org/springblade/core/oss/rule/OssRule.java
public interface OssRule {
    String bucketName(String bucketName);   // 存储桶命名规则
    String fileName(String originalFilename); // 文件命名规则
}
```

- `BladeOssRule` 是默认实现，根据系统配置动态选择 Minio / 阿里云 OSS / 腾讯云 COS / 七牛云 / 华为云 OBS / AWS S3 / 本地存储
- 各 Provider Template: `MinioTemplate`、`AliossTemplate`、`TencentCosTemplate`、`QiniuTemplate`、`HuaweiObsTemplate`、`S3Template`、`LocalFileTemplate`

**SMS 短信**:

- 接口: `SmsTemplate`（`bladex-tool/blade-starter-sms/src/main/java/org/springblade/core/sms/SmsTemplate.java`）
- 实现: `AliSmsTemplate`、`TencentSmsTemplate`、`QiniuSmsTemplate`、`YunpianSmsTemplate`
- 通过 `SmsEnum` 枚举和配置决定使用哪个提供商

### 1.3 观察者模式 — 事件监听

**核心思想**: 基于 Spring 事件机制，异步处理日志记录等耗时操作，不阻塞主流程。

```java
// 源码: bladex-tool/blade-starter-log/src/main/java/org/springblade/core/log/event/
// 事件类
ApiLogEvent      // API 日志事件
UsualLogEvent    // 普通日志事件
ErrorLogEvent    // 错误日志事件

// 监听器类
ApiLogListener      // 监听 API 日志事件
UsualLogListener    // 监听普通日志事件
ErrorLogListener    // 监听错误日志事件
```

**使用方式**:
```java
// 发布事件（在需要记录日志的地方）
applicationContext.publishEvent(new ApiLogEvent(logApi));
// 监听器异步消费事件，写入日志表
```

### 1.4 拦截器模式 — MyBatis 插件

**核心思想**: 通过 MyBatis-Plus 拦截器插件，在 SQL 执行前后自动注入租户条件、数据权限条件等。

- **租户拦截器**: 自动在 SQL 中追加 `tenant_id = ?` 条件
- **数据权限拦截器**: 根据角色配置自动追加数据过滤条件（如 `create_dept IN (...)`）
- **数据记录拦截器**: `BladeRecorderInterceptor` 拦截方法执行，对比 `@DataRecord` / `@FieldRecord` 注解标注的字段变化

```java
// 源码: bladex-tool/blade-starter-data-record/src/main/java/org/springblade/core/datarecord/interceptor/BladeRecorderInterceptor.java
```

### 1.5 SPI 扩展 — LauncherService

**核心思想**: 基于 Java `ServiceLoader` 实现启动生命周期扩展点。

```java
// 源码: bladex-tool/blade-core-launch/src/main/java/org/springblade/core/launch/service/LauncherService.java
public interface LauncherService extends Ordered, Comparable<LauncherService> {
    void launcher(SpringApplicationBuilder builder, String appName, String profile);
    void init(Environment environment, String appName, String profile);
    void starter(Environment environment, String appName, String profile);
}
```

**生命周期**: `init()` -> `launcher()` -> `starter()`

**内置实现**:
| 实现类 | 用途 | 源码位置 |
|--------|------|----------|
| `LogLauncherServiceImpl` | 初始化日志配置 | `bladex-tool/blade-core-log4j2/` 或 `blade-starter-log/` |
| `SwaggerLauncherServiceImpl` | 初始化 Swagger 文档 | `bladex-tool/blade-starter-swagger/` |
| `LiteFlowLauncherServiceImpl` | 初始化 LiteFlow 规则引擎 | `bladex-tool/blade-starter-liteflow/` |

**注册方式**: 在 `META-INF/services/org.springblade.core.launch.service.LauncherService` 文件中声明实现类全限定名。

### 1.6 模板方法 — BladeController

**核心思想**: 封装 Controller 层的通用操作，子类继承后可直接使用便捷方法。

```java
// 源码: bladex-tool/blade-core-boot/src/main/java/org/springblade/core/boot/ctrl/BladeController.java
public class BladeController {
    public <T> R<T> data(T data);             // 返回数据
    public R success(String message);         // 返回成功
    public R fail(String message);            // 返回失败
    public R status(boolean flag);            // 返回状态
    public BladeUser getUser();               // 获取当前用户
    public LocalFile getFile(MultipartFile file); // 获取文件对象
}
```

## 2. 最佳实践

### 2.1 Service 层规范

**继承体系**:
```
IService<T> (MyBatis-Plus)
    └── BaseService<T> (BladeX 扩展)
            └── BaseServiceImpl<M, T> (实现类)
```

- Service 接口继承 `BaseService<T>`（`bladex-tool/blade-starter-mybatis/src/main/java/org/springblade/core/mp/base/BaseService.java`）
- Service 实现类继承 `BaseServiceImpl<M, T>`
- `BaseService` 提供了 `queryOne()`、`queryDetail()`、`deleteLogic()`、`changeStatus()`、`isFieldDuplicate()` 等常用方法

**示例**:
```java
// Service 接口
public interface UserService extends BaseService<User> { }

// Service 实现
@Service
public class UserServiceImpl extends BaseServiceImpl<UserMapper, User> implements UserService { }
```

### 2.2 Controller 层规范

- Controller 继承 `BladeController`，获得 `data()`、`success()`、`fail()`、`getUser()` 等便捷方法
- 返回值统一使用 `R<T>` 包装（`org.springblade.core.tool.api.R`）
- 列表查询使用 `IPage<T>` 分页对象
- 安全相关接口使用 `@PreAuth`、`@IsAdmin` 等注解

**示例**:
```java
@RestController
@AllArgsConstructor
@RequestMapping("/blade-system/user")
public class UserController extends BladeController {
    private final IUserService userService;

    @GetMapping("/list")
    @PreAuth("hasPermission('user:list')")
    public R<IPage<UserVO>> list(UserQueryDTO dto) {
        return data(userService.selectUserPage(Condition.getPage(dto), dto));
    }
}
```

### 2.3 缓存使用规范

**缓存工具类**: `CacheUtil`

**命名空间**: 统一使用 `CacheConstant` 中定义的常量

```java
// 源码: bladex-tool/blade-starter-cache/src/main/java/org/springblade/core/cache/constant/CacheConstant.java
CacheUtil.get(SYS_CACHE, "menu:auth", userId, List.class, Boolean.FALSE);
CacheUtil.put(SYS_CACHE, "menu:auth", userId, permissions, Boolean.FALSE);
CacheUtil.clear(SYS_CACHE);
```

**关键规则**:
- `Boolean.FALSE` 表示不设置过期时间（TTL），需依赖手动清除
- 修改权限数据后必须调用 `CacheUtil.clear()` 清除相关缓存
- 不同业务使用不同的缓存命名空间，避免冲突

### 2.4 多租户开发规范

- 需要租户隔离的实体继承 `TenantEntity`，不需要则继承 `BaseEntity`
- 系统级查询（跨租户）在方法上加 `@NonDS` 注解
- 强制使用租户数据源的方法上加 `@TenantDS` 注解
- 不要手动在 SQL 中写 `tenant_id = ?`，由 MyBatis-Plus 租户插件自动注入

### 2.5 Wrapper 模式

**核心思想**: 将 Entity 到 VO 的转换逻辑封装在 Wrapper 类中，避免在 Controller 或 Service 中散落转换代码。

**继承体系**:
```
EntityWrapper<T, V> (BladeX)
    └── BaseEntityWrapper<T, V> (继承 BaseEntity 的包装)
```

- 源码: `bladex-tool/blade-starter-mybatis/src/main/java/org/springblade/core/mp/support/BaseEntityWrapper.java`

**示例**:
```java
// 源码: bladex-boot/src/main/java/org/springblade/modules/system/wrapper/UserWrapper.java
public class UserWrapper extends BaseEntityWrapper<User, UserVO> {
    public static UserWrapper build() {
        return new UserWrapper();
    }

    @Override
    public UserVO entityVO(User user) {
        UserVO userVO = BeanUtil.copyProperties(user, UserVO.class);
        // 填充关联数据：部门名称、角色名称、岗位名称等
        userVO.setDeptName(SysCache.getDeptName(userVO.getDeptId()));
        userVO.setRoleName(SysCache.getRoleName(userVO.getRoleId()));
        return userVO;
    }
}

// 在 Service 中使用
List<UserVO> voList = UserWrapper.build().listVO(userList);
```

## 3. 常见陷阱

### 3.1 role_id 逗号分隔存储

**问题**: `BladeUser.roleId` 是逗号分隔字符串（如 `"1,2,3"`），不是集合。

**后果**: 直接使用 `roleId.equals(...)` 会导致匹配失败。

**正确处理**:
```java
// 错误
if (user.getRoleId().equals("1")) { ... }

// 正确
List<String> roleIds = StringUtil.split(user.getRoleId(), StringPool.COMMA);
if (roleIds.contains("1")) { ... }
```

**源码参考**: `bladex-tool/blade-core-auth/blade-core-secure/src/main/java/org/springblade/core/secure/handler/BladePermissionHandler.java` 第111行

### 3.2 菜单非租户隔离

**问题**: `blade_menu` 表没有 `tenant_id` 字段，菜单是全局共享的。

**后果**: 新增的菜单对所有租户可见（但需要通过角色授权才能访问）。

**注意**: 如果某些菜单只希望特定租户使用，需要在角色授权层面控制，而不是在菜单层面。

### 3.3 缓存不一致

**问题**: 权限相关缓存不设置自动过期（`Boolean.FALSE`），修改数据后不会自动失效。

**后果**: 修改角色权限、菜单分配后，用户仍然使用旧的权限直到缓存被手动清除或重启服务。

**解决**: 在修改操作后显式清除缓存：
```java
// 修改角色权限后
CacheUtil.clear(SYS_CACHE);
CacheUtil.clear(RESOURCE_CACHE);
```

### 3.4 逻辑删除与唯一约束

**问题**: `@TableLogic` 标注的字段在"删除"后仍保留在数据库中（`is_deleted=1`）。

**后果**: 如果某字段有唯一索引，软删除后再插入相同值会报唯一约束冲突。

**解决**:
- 方案一: 唯一索引改为联合唯一索引，包含 `is_deleted` 字段
- 方案二: 业务层在插入前检查是否已存在（包括已软删除的记录）
- 方案三: 使用 `isFieldDuplicate()` 方法检查重复

### 3.5 数据权限 scope_type 理解

**问题**: `scope_type` 不是简单的枚举值，而是与 `scope_column`、`scope_value`、`scope_class` 配合使用的规则标识。

**正确理解**:
- `scope_type`: 对应 `DataScopeEnum` 的 5 种类型（1=全部, 2=本人, 3=本部门, 4=本部门及以下, 5=自定义）
- `scope_column`: SQL 过滤字段名（如 `create_dept`）
- `scope_value`: 自定义值（当 scope_type=5 时使用）
- `scope_class`: 区分 Mapper 级别还是 Service 级别

### 3.6 Token 中的 role_id 分割

**问题**: JWT Token Payload 中的 `role_id` 是逗号分隔字符串，权限校验时需要分割。

**后果**: 忘记分割会导致角色匹配失败。

**源码参考**: `BladePermissionHandler` 中将 `roleId` 字符串分割为 `List<String>` 后再传入 SQL `IN` 查询。

## 4. 新增业务模块指南

### 4.1 包结构分层

在 `bladex-boot/src/main/java/org/springblade/modules/{模块名}/` 下创建标准分层:

```
modules/{模块名}/
├── controller/     # 控制器（继承 BladeController）
├── service/        # 服务接口（继承 BaseService<T>）
│   └── impl/       # 服务实现（继承 BaseServiceImpl<M, T>）
├── mapper/         # MyBatis Mapper 接口
├── pojo/
│   ├── entity/     # 实体类（继承 TenantEntity 或 BaseEntity）
│   ├── vo/         # 视图对象
│   └── dto/        # 数据传输对象 / 查询参数
├── wrapper/        # Entity -> VO 包装类（继承 BaseEntityWrapper）
└── excel/          # Excel 导入导出（可选）
```

**Mapper XML 位置**: `bladex-boot/src/main/resources/mapper/{模块名}/`

### 4.2 注册 Swagger

新模块的 Controller 需要添加 Swagger 注解:

```java
@RestController
@AllArgsConstructor
@RequestMapping("/blade-system/xxx")
@Tag(name = "XXX管理", description = "XXX")
public class XxxController extends BladeController {
    @Operation(summary = "列表", description = "分页查询列表")
    @GetMapping("/list")
    public R<IPage<XxxVO>> list(XxxDTO dto) { ... }
}
```

确保 `bladex-tool/blade-starter-swagger` 依赖已引入，`SwaggerLauncherServiceImpl` 会自动扫描注册。

### 4.3 配置安全

**跳过鉴权的接口** — 在 `SecureRegistry` 配置类中添加:

```java
@Configuration
public class SecureConfiguration {
    @Bean
    public SecureRegistry secureRegistry() {
        return new SecureRegistry()
            .skipUrls("/xxx/public/**", "/xxx/health");
    }
}
```

**需要鉴权的接口** — 使用 `@PreAuth` 注解:

```java
@PreAuth("hasPermission('xxx:add')")   // 接口权限
@PreAuth("hasRole('admin')")            // 角色权限
@PreAuth("hasMenu('xxx')")              // 菜单权限
@PreAuth("#entity.id < 10")            // SpEL 表达式
```

### 4.4 Mapper XML 位置

```
bladex-boot/src/main/resources/mapper/{模块名}/XxxMapper.xml
```

**注意事项**:
- 使用 MyBatis-Plus 时，简单的 CRUD 不需要写 XML
- 复杂查询（关联查询、分组统计等）才需要 XML
- XML 中不要手动写 `tenant_id` 条件，由插件自动注入
- 逻辑删除条件由 `@TableLogic` 自动处理

## 5. TokenGranter 扩展指南（新增登录方式）

### 5.1 步骤

1. **创建 Granter 实现类**，继承 `AbstractTokenGranter`:

```java
@Component
public class MyCustomTokenGranter extends AbstractTokenGranter {

    @Override
    public String type() {
        return "my_custom"; // 自定义 grantType
    }

    @Override
    public OAuth2User user(OAuth2Request request) {
        // 根据 request 中的参数（如自定义凭证）查询用户
        String customToken = request.getParameter("custom_token");
        // ... 验证逻辑
        return new OAuth2User(userInfo);
    }
}
```

2. **在 OAuth2Properties 中注册启用状态**（可选，如果需要配置开关）

3. **在 `OAuth2GranterConstant` 中添加常量**（建议）:

```java
String MY_CUSTOM = "my_custom";
```

4. **前端调用**:

```http
POST /oauth/token?grant_type=my_custom&custom_token=xxx&tenant_id=xxx
```

### 5.2 增强器扩展

如果需要增强 TokenGranter 的行为（如添加额外逻辑），可以实现 `TokenGranterEnhancer`:

```java
@Component
public class MyGranterEnhancer implements TokenGranterEnhancer {
    @Override
    public String type() {
        return "my_custom";
    }

    @Override
    public void enhance(OAuth2User user, OAuth2Request request, OAuth2Token token) {
        // 在 Token 生成后执行增强逻辑
    }
}
```

## 8. 事件监听扩展指南

### 8.1 新增自定义事件

1. **创建事件类**（继承 `ApplicationEvent`）:

```java
public class MyBusinessEvent extends ApplicationEvent {
    private final String action;
    private final Long targetId;

    public MyBusinessEvent(Object source, String action, Long targetId) {
        super(source);
        this.action = action;
        this.targetId = targetId;
    }
}
```

2. **创建监听器类**:

```java
@Component
public class MyBusinessEventListener {

    @Async
    @EventListener
    public void handleMyEvent(MyBusinessEvent event) {
        // 异步处理业务事件
    }
}
```

3. **发布事件**:

```java
@Autowired
private ApplicationContext applicationContext;

public void doSomething() {
    // ... 业务逻辑
    applicationContext.publishEvent(new MyBusinessEvent(this, "create", id));
}
```

### 8.2 参考 BladeX 日志事件

参考 `bladex-tool/blade-starter-log` 中的事件/监听器实现:

- 事件: `ApiLogEvent`、`UsualLogEvent`、`ErrorLogEvent`
- 监听器: `ApiLogListener`、`UsualLogListener`、`ErrorLogListener`
- 特点: 使用 `@Async` 异步执行，`@EventListener` 监听
