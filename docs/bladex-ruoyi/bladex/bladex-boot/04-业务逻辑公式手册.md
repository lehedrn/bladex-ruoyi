## 1. 密码与加密

### 1.1 密码存储加密

**算法**: `SHA1(MD5(明文))` (非 BCrypt)

**来源**: `DigestUtil.encrypt()` - `sources/bladex/bladex-tool/blade-core-tool/src/main/java/org/springblade/core/tool/utils/DigestUtil.java:452`

```java
// 密码存储加密: 先 MD5 再 SHA1
public static String encrypt(String data) {
    if (StringUtil.isBlank(data)) {
        return StringPool.EMPTY;
    }
    return sha1Hex(md5Hex(data));
}
```

**执行流程**:
1. 用户输入明文密码: `"password123"`
2. 第一步 MD5: `md5Hex("password123")` -> 32位十六进制字符串
3. 第二步 SHA1: `sha1Hex(md5结果)` -> 40位十六进制字符串
4. 存储到 blade_user.password 字段

### 1.2 密码传输加密 (SM2)

**算法**: 国密 SM2 非对称加密 (Bouncy Castle 实现)

**来源**:
- `SM2Util` - `sources/bladex/bladex-tool/blade-core-tool/src/main/java/org/springblade/core/tool/utils/SM2Util.java`
- `OAuth2PasswordHandler` - `sources/bladex/bladex-tool/blade-core-auth/blade-core-oauth2/src/main/java/org/springblade/core/oauth2/handler/OAuth2PasswordHandler.java`

```java
// 登录密码校验流程
public boolean matches(String rawPassword, String encodedPassword) {
    // 1. 获取 SM2 公钥/私钥 (配置在 OAuth2Properties)
    String publicKey = properties.getPublicKey();
    String privateKey = properties.getPrivateKey();

    // 2. 使用 SM2 私钥解密前端传来的密码
    String decryptPassword = SM2Util.decrypt(rawPassword, publicKey, privateKey);

    // 3. 解密后二次加密与数据库对比
    return encodedPassword.equals(encode(decryptPassword));
}

// encode 即 DigestUtil.encrypt(raw) -> SHA1(MD5(raw))
```

**传输流程**:
```
前端: 明文密码 -> SM2公钥加密 -> 提交密文
后端: SM2私钥解密 -> SHA1(MD5(解密明文)) -> 对比数据库
```

### 1.3 弱密码列表

系统中未内置弱密码列表, 但可通过 `blade_param` 表配置 `account.failCount` 等参数控制登录策略。

### 1.4 License 解密

租户表 `blade_tenant.licenseKey` 字段存储授权码。SM2 的 `decrypt()` 方法中包含签名校验逻辑:

```java
// SM2Util.decrypt(String encrypted, String publicKey, String privateKey)
public static String decrypt(String encrypted, String publicKey, String privateKey) {
    // 空密钥直接返回失败
    if (StringUtil.isAnyBlank(publicKey, privateKey)) {
        return StringPool.EMPTY;
    }
    // 补充 04 前缀
    if (!StringUtil.startsWithIgnoreCase(encrypted, ENCRYPT_PREFIX)) {
        encrypted = ENCRYPT_PREFIX + encrypted;
    }
    // 解密
    String decrypted = SM2Util.decrypt(encrypted, privateKey);
    // 签名校验 (SM2 签名验证)
    boolean isVerified = SM2Util.verify(decrypted, SM2Util.sign(decrypted, privateKey), publicKey);
    // 仅签名通过才返回解密结果
    return isVerified ? decrypted : StringPool.EMPTY;
}
```

### 2.4 数据权限 SQL 生成 (5 种 scope_type)

**来源**: `BladeDataScopeHandler.sqlCondition()` - `sources/bladex/bladex-tool/blade-starter-data-scope/src/main/java/org/springblade/core/datascope/handler/BladeDataScopeHandler.java:53`

#### 类型 1: ALL (全部数据)

**条件**: `scope_type = 1` 或用户角色包含 `administrator`

```sql

```

#### 类型 2: OWN (本人可见)

```sql
-- 原始 SQL: SELECT * FROM blade_order
-- 改写后:
SELECT * FROM (
    SELECT * FROM blade_order
) scope WHERE scope.#{scopeColumn} IN (#{bladeUser.userId})
```

**伪代码**:
```java
ids.add(bladeUser.getUserId());
return String.format("select %s from (%s) scope where scope.%s in (%s)",

```

#### 类型 3: OWN_DEPT (所在机构可见)

```sql

    SELECT * FROM blade_order
```

## 5. 账户锁定公式

### 5.1 失败计数 Redis Key

**来源**: `CacheNames.java` + `BladeLockHandler.java`

| 类型 | Redis Key 格式 | 示例 |
|------|----------------|------|
| 账号失败计数 | `{tenantId}:blade:lock::account:fail:{account}` | `000000:blade:lock::account:fail:admin` |
| IP 失败计数 | `{tenantId}:blade:lock::ip:fail:{ip}` | `000000:blade:lock::ip:fail:192.168.1.1` |
| 验证码 | `blade:auth::blade:captcha:{captchaKey}` | `blade:auth::blade:captcha:abc123` |

### 5.2 锁定阈值与时间

**来源**: `BladeAuthConstant.java` + `BladeLockHandler.java`

| 参数 | 值 | 来源 |
|------|------|------|
| 锁定阈值 | 默认 5 次 | `FAIL_COUNT = 5`, 可通过 `blade_param` 表 `account.failCount` 覆盖 |
| 锁定时长 | 30 分钟 | `LOCK_DURATION_MINUTES = 30` (硬编码) |
| Redis 过期 | 30 分钟 | `Duration.ofMinutes(LOCK_DURATION_MINUTES)` |

### 5.3 锁定校验逻辑

```java
// BladeLockHandler.validateAccountLock()
public OAuth2Validation validateAccountLock(String tenantId, String account) {
    int cnt = getAccountFailCount(tenantId, account);
    int failCount = getFailCountThreshold();  // 默认 5
    if (cnt >= failCount) {
        // 已锁定, 拒绝登录
        return buildValidationFailure();
    }
    return new OAuth2Validation();  // 未锁定
}
```

### 5.4 失败计数增加

```java
// BladeLockHandler.addAccountFailCount()
public void addAccountFailCount(String tenantId, String account) {
    int count = getAccountFailCount(tenantId, account);
    String cacheKey = CacheNames.tenantKey(tenantId, CacheNames.ACCOUNT_FAIL_KEY, account);
    bladeRedis.setEx(cacheKey, count + 1, Duration.ofMinutes(30));
}
```

### 5.5 锁定/解锁逻辑

| 事件 | 操作 |
|------|------|
| 认证成功 | 清空账号失败计数 + 清空 IP 失败计数 |
| 认证失败 | 增加账号失败计数 + 增加 IP 失败计数 |
| 达到阈值 | 账号锁定 (30 分钟后 Redis key 自动过期解锁) |
| 手动解锁 | 调用 `clearAccountFailCount()` 删除 Redis key |

```java
// 认证成功 - 清空计数
public void handleAuthSuccess(String tenantId, String account) {
    clearAccountFailCount(tenantId, account);
    clearIpFailCount(tenantId);
}

// 认证失败 - 增加计数
public void handleAuthFailure(String tenantId, String account) {
    addAccountFailCount(tenantId, account);
    addIpFailCount(tenantId);
}
```

## 6. 部门树查询公式

### 6.1 子部门查询 (利用 ancestors 字段)

**来源**: `DataScopeConstant.DATA_BY_DEPT`

```sql
-- ancestors 格式: "0,100,200" (从根到当前节点的 ID 路径)
-- 查询部门 ID=100 的所有子部门 (包含自身)
SELECT id FROM blade_dept
WHERE ancestors LIKE CONCAT(CONCAT('%', '100'), '%')
  AND is_deleted = 0;

-- 等价于: WHERE ancestors LIKE '%100%'
```

**原理**: ancestors 字段包含所有父级 ID, 通过 `LIKE '%deptId%'` 可一次性查出所有子孙部门, 无需递归查询。

### 6.2 部门路径查询

```sql
-- 查询某个部门的完整路径 (从根到当前部门)
SELECT id, dept_name, ancestors
FROM blade_dept
WHERE id = ?
  AND is_deleted = 0;

-- ancestors 即为完整路径, 逗号分隔
-- 例如 ancestors = "0,100,200,300"
-- 解析: 顶级 -> 部门100 -> 部门200 -> 当前部门300
```

### 6.3 获取部门列表 (数据权限)

```sql
-- scope_type = 4 (OWN_DEPT_CHILD) 时, 获取用户可见的所有部门 ID
-- 1. 获取用户主部门及其子部门
SELECT id FROM blade_dept
WHERE ancestors LIKE CONCAT(CONCAT('%', #{userDeptId}), '%')
  AND is_deleted = 0;

-- 2. 如果用户有多个部门 (blade_user_dept 表)
SELECT ud.dept_id FROM blade_user_dept ud
WHERE ud.user_id = ?
  AND ud.is_deleted = 0;
```

## 8. 隐式业务规则

### 8.1 用户创建流程

```
1. 前端提交注册/新增用户表单
   -> 密码字段经 SM2 公钥加密后传输

2. 后端接收参数
   -> SM2 私钥解密获取明文密码
   -> 二次加密: SHA1(MD5(明文)) 存入 blade_user.password

3. 设置默认值
   -> tenantId: 当前上下文租户 ID (默认 "000000")
   -> status: 1 (正常)
   -> isDeleted: 0 (未删除)
   -> createUser/updateUser: 当前用户 ID
   -> createTime/updateTime: 当前时间

4. 关联角色/部门
   -> roleId: 逗号分隔的角色 ID 列表
   -> deptId: 逗号分隔的部门 ID 列表
   -> 如需多对多关联, 写入 blade_user_dept 表
```

### 8.2 菜单路由生成

```sql
-- 1. 根据用户 roleId 查询关联菜单
SELECT DISTINCT m.*
FROM blade_menu m
INNER JOIN blade_role_menu rm ON rm.menu_id = m.id
WHERE rm.role_id IN (#{roleId列表})
  AND m.is_deleted = 0
ORDER BY m.sort;

-- 2. 根据租户套餐过滤菜单 (可选)
-- 如果租户有 packageId, 还需校验菜单在套餐范围内:
-- tenantPackage.menuId (逗号分隔) 是否包含当前菜单 ID

-- 3. 前端根据 category 字段区分:
--    category=1 -> 渲染为菜单导航项
--    category=2 -> 渲染为按钮/操作权限
```

### 8.3 数据权限与租户隔离叠加

```
请求进入 -> 租户拦截器添加 tenant_id 条件 (自动)
         -> 数据权限拦截器添加 scope 条件 (按角色配置)

叠加效果 SQL:
SELECT * FROM blade_order
WHERE tenant_id = #{tenantId}           -- 租户隔离 (MyBatis-Plus 自动添加)
  AND create_dept IN (#{deptId列表})    -- 数据权限 (BladeDataScopeHandler 添加)
  AND is_deleted = 0;

特殊情况: blade_user 表被排除在租户自动过滤之外,
          需业务代码手动添加 tenant_id 条件
```

### 8.5 验证码 Redis Key 格式

**来源**: `CacheNames.CAPTCHA_KEY`

```
Key 格式: blade:auth::blade:captcha:{captchaKey}
TTL: 通常 2-5 分钟 (验证码有效期)

示例: blade:auth::blade:captcha:a1b2c3d4
```

**校验流程**:
```java
// 1. 前端请求验证码 -> 后端生成图形验证码
// 2. 将验证码答案存入 Redis: bladeRedis.set(captchaKey, answer, TTL)
// 3. 前端提交 login -> 携带 captchaKey + captchaAnswer
// 4. 后端校验: bladeRedis.get(captchaKey) == captchaAnswer
// 5. 校验成功后删除 Redis key
```
