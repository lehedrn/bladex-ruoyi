## 2. 纠正对照表

| 易混淆说法 | 正确术语 | 说明 |
|-----------|---------|------|
| "用户 Token" | `Blade-Auth` Header 中的 JWT | Token 不是存储在 Cookie 或 Session 中，而是通过 `Blade-Auth` HTTP Header 传递 |
| "数据权限类型" | `DataScopeEnum` 的 5 种值 | 不要与 `ApiScope`（API 权限）混淆，DataScope 是行级数据过滤，ApiScope 是接口级访问控制 |
| "角色 ID 列表" | `roleId` 逗号分隔字符串 | `BladeUser.roleId` 是逗号分隔的字符串（如 `"1,2,3"`），不是 `List<Long>`。使用前需要 `split(",")` |
| "租户隔离" | 通过 `tenant_id` 字段 + MyBatis-Plus 租户插件 | 不是物理数据库隔离（除非引入对应的 tenant starter） |
| "菜单权限" | `blade_role_menu` 表关联 | 菜单（Menu）和权限（Scope/API）是两个不同的概念，菜单对应页面导航，权限对应接口访问 |
| "逻辑删除" | `@TableLogic` + `is_deleted` 字段 | 删除操作不会物理删除记录，而是将 `is_deleted` 设为 1。查询时自动追加 `is_deleted = 0` 条件 |
| "文件附件 ID" | `attachId` 在 `BladeFile/LocalFile` 中 | 文件上传后返回的 `attachId` 用于关联 `blade_attach` 表中的附件记录 |
| "OssBuilder" | 实际叫 `OssRule` / `BladeOssRule` | BladeX 中没有 `OssBuilder` 类，规则链接口名为 `OssRule`，实现为 `BladeOssRule` |
| "SmsBuilder" | 实际通过 `SmsTemplate` + 配置选择 | BladeX 中没有 `SmsBuilder` 类，短信通过 `SmsTemplate` 接口和配置枚举 `SmsEnum` 选择提供商 |
| "自定义数据源" | `@NonDS` / `@TenantDS` 注解控制 | 不是通过配置文件切换数据源，而是通过方法注解动态切换 |

## 4. 隐式决策点

以下是在阅读源码或二次开发时需要理解的隐性设计决策：

### 4.1 角色 ID 的存储方式

- `BladeUser.roleId` 是 **逗号分隔的字符串**（如 `"1,2,3"`），不是集合
- `blade_role_scope` 表中的 `role_id` 也是字符串类型（`IN` 查询时需要分割）
- 这意味着在 SQL 中需要通过 `IN (?)` 配合多参数绑定，而不是单值匹配
- **开发注意**：查询角色关联数据时，需要将逗号分隔的 roleId 分割后传入 SQL

### 4.2 菜单不是租户隔离的

- `blade_menu` 表 **没有 `tenant_id` 字段**
- 菜单是全局共享的，通过 `blade_role_menu` 关联角色来控制可见性
- 不同租户的角色可以拥有不同的菜单组合，但菜单本身是全局的
- **开发注意**：新增菜单时不需要考虑租户维度

### 4.3 缓存一致性策略

- 权限数据（菜单、角色、API 范围）查询后写入 Redis 缓存
- 缓存的失效依赖 **手动清除**（修改角色/菜单后调用 `CacheUtil.clear()`）
- 没有设置自动过期时间（`Boolean.FALSE` 参数表示不设置 TTL）
- **开发注意**：修改权限相关数据后，必须手动清除对应缓存，否则用户看到的仍是旧数据

### 4.4 逻辑删除与唯一约束的冲突

- 使用 `@TableLogic` 后，删除的记录仍存在数据库中（`is_deleted=1`）
- 如果字段有唯一索引，"删除"后再"新增"相同值的记录会冲突
- **开发注意**：需要唯一性约束的字段应考虑软删除场景，或在唯一索引中包含 `is_deleted`

### 4.5 Token 中的 role_id 分割

- JWT Token 中编码的 `role_id` 是逗号分隔字符串
- 权限校验时（`BladePermissionHandler`），需要先 `split(",")` 转为列表
- **开发注意**：自定义权限校验逻辑时，别忘了分割 roleId

### 4.6 数据权限 scope_type 的理解

- `scope_type` 不是 DataScopeEnum 的 1-5 值，而是 `blade_scope_data` 表中配置的 **规则类型标识**
- 实际的可见范围由 `scope_type` + `scope_value` + `scope_column` 组合决定
- `scope_class` 区分是 Mapper 级别还是 Service 级别的数据权限
- **开发注意**：扩展数据权限规则时，需要在 `blade_scope_data` 表中配置对应记录

### 4.7 微服务模式默认关闭

- `bladex-boot` 的 `pom.xml` 中排除了 `blade-core-cloud`
- 默认是单体架构，微服务模式需要手动引入 cloud starter
- **开发注意**：不要假设 Feign 调用可用，确认项目部署模式

### 4.8 多租户数据源切换

- 默认是 **字段隔离模式**（所有租户共享一个数据库，通过 `tenant_id` 区分）
- 切换为 **数据库隔离模式** 需要引入对应的 tenant starter 并配置数据源
- `@NonDS` 和 `@TenantDS` 注解可以精确控制方法级别的数据源选择
- **开发注意**：跨租户查询或系统级查询需要使用 `@NonDS` 避免被自动切换
