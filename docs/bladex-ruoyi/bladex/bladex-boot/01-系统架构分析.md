# 01_系统架构分析文档 — BladeX-Boot

> **分析日期**: 2026-05-21  
> **源文件路径**: sources/bladex/bladex-boot/src/main/java/org/springblade/  
> **数据库脚本**: sources/bladex/bladex-boot/doc/sql/bladex/bladex.mysql.all.create.sql  
> **核心结论**: BladeX-Boot 是基于 BladeX-Tool 框架的业务应用单体，采用 RBAC + 数据权限 + 多租户的三层安全模型，通过 OAuth2 统一认证、MyBatis 拦截器实现数据隔离，涵盖用户/角色/菜单/部门/字典/租户等 22 个系统管理模块及工作流、任务调度、代码生成等扩展能力。

---

## 1. 技术架构全景

### 1.1 系统定位

BladeX-Boot 是 BladeX 平台的**业务应用层**，依赖 `blade-core-boot` 框架聚合模块，专注于业务逻辑实现。

| 维度 | 说明 |
|------|------|
| 架构模式 | 单体应用（Monolith），可升级为微服务 |
| 启动方式 | `BladeApplication.run()` 包装的 Spring Boot |
| Web 服务器 | Undertow (16 IO 线程, 400 Worker 线程) |
| 会话管理 | Redis Session (`@EnableRedisHttpSession`) |
| 定时任务 | `@EnableScheduling` + PowerJob 分布式调度 |

### 1.2 技术栈

| 类别 | 技术 | 版本/说明 |
|------|------|----------|
| ORM | MyBatis-Plus | 雪花 ID、逻辑删除、自动填充 |
| 连接池 | Druid | 初始 5, 最大 20, 超时 2s |
| 缓存 | Redis (Protostuff 序列化) | 缓存 + Session + 分布式锁 |
| 数据库 | MySQL 8.3 | 也支持 PG/Oracle/SQLServer/达梦/金仓 |
| 认证 | 自研 OAuth2 | JWT Token, SM2 加密传输 |
| 工作流 | Flowable | 7.0.1, 宋体渲染 |
| 任务调度 | PowerJob | 4.3.9, 默认禁用 |
| 代码生成 | MyBatis-Plus Generator + Beetl | 模板化代码生成 |
| API 文档 | Knife4j (OpenAPI3) | 4.5.0 |
| 报表 | UReport2 | 默认禁用 |
| 对象存储 | MinIO/AliOSS/Qiniu/Tencent/Huawei/AWS | 链式规则选择 |
| 短信 | 阿里云/七牛/腾讯/云片 | 链式规则选择 |
| 验证码 | easy-captcha | 图形验证码 |
| 社交登录 | JustAuth | GitHub/Gitee/微信/QQ/钉钉 |

## 3. 核心类关系与继承体系

### 3.1 启动相关类

| 类名 | 路径 | 职责 |
|------|------|------|
| `Application` | org.springblade | 启动入口，@EnableScheduling + @EnableRedisHttpSession |
| `BladeConfiguration` | common/config | 安全注册表、CORS、OAuth2 端点路径前缀 |
| `BladeHandlerConfiguration` | common/config | 注册数据审计/数据权限/权限校验 Handler |
| `BladeAuthConfiguration` | modules/auth/config | 注册 OAuth2 Handler/Service Bean |
| `SwaggerConfiguration` | common/config | 注册 3 个 OpenAPI 分组 |
| `LauncherServiceImpl` | common/launch | SPI 实现，启动时初始化配置 |

### 3.2 安全认证类

| 类名 | 路径 | 职责 |
|------|------|------|
| `BladeAuthorizationHandler` | modules/auth/handler | OAuth2 前置验证、租户校验、锁定处理 |
| `BladeUserDetailService` | modules/auth/service | 用户详情加载（按 ID/账号/手机） |
| `BladeClientDetailService` | modules/auth/service | OAuth2 客户端详情加载（JDBC 查 blade_client） |
| `BladePasswordHandler` | modules/auth/handler | BCrypt 密码匹配 |
| `BladeTokenHandler` | modules/auth/handler | JWT Token 增强（添加 account 字段） |
| `BladeLockHandler` | modules/auth/handler | 账户/IP 锁定（Redis 计数，5 次/30 分钟） |
| `BladePermissionHandler` | common/handler | API 权限校验（hasPermission/hasMenu/permissionAll） |
| `SecureInterceptor` | blade-core-secure | 安全拦截器（框架层） |

### 3.3 TokenGranter 策略模式

| Granter | grantType | 职责 |
|---------|-----------|------|
| `CaptchaTokenGranter` | `captcha_code` | 验证码登录，验证 Redis 验证码后委托密码登录 |
| `SmsTokenGranter` | `sms_code` | 短信登录，验证 SMS 码后按手机号查找用户 |
| `SocialTokenGranter` | `social` | 社交登录，JustAuth OAuth 回调 → UserOauth 映射 |
| `RegisterTokenGranter` | `register` | 自助注册，校验用户名/密码/手机/邮箱格式 |

## 4. 核心业务流程时序图

### 4.1 用户登录流程（完整版）

```
客户端 → POST /blade-auth/oauth/token
  → CaptchaTokenGranter (验证验证码)
    → BladeAuthorizationHandler.preValidation()
        → 弱密码检查 (生产环境)
        → BladeLockHandler.validateAccountLock()
        → BladeLockHandler.validateIpLock()
    → BladeUserDetailService.loadByUsername()
        → UserCache 缓存检查
        → DB: SELECT FROM blade_user WHERE tenant_id + account
    → BladePasswordHandler.matches()
        → BCrypt.check(明文, 存储哈希)
    → BladeAuthorizationHandler.authValidation()
        → 租户状态验证 (存在/启用/未过期)
        → License 验证 (如启用)
    → BladeTokenHandler.enhance()
        → JWT Payload: user_id, tenant_id, role_id, dept_id, account, client_id, user_type
    → BladeAuthorizationHandler.authSuccessful()
        → BladeLockHandler.handleAuthSuccess() 清除计数
  ← 返回 {access_token, refresh_token, expire}
```

### 4.3 权限验证流程

```
HTTP 请求 → SecureInterceptor
  → 跳过 URL 检查 (BladeConfiguration.secureRegistry)
      /blade-auth/**, /doc.html, /swagger-resources/**, /druid/** 等
  → 提取 JWT Token (Header: Blade-Auth)
  → JWT 解码验证 → 提取 BladeUser (userId, tenantId, roleId, account, deptId)
  → BladePermissionHandler
      → permissionAll(): 检查 URI 前缀是否在角色 API 权限路径中
          缓存 Key: SYS_CACHE:apiScope:role:{roleId}
      → hasPermission(code): 检查权限码是否在角色权限中
          缓存 Key: SYS_CACHE:apiScope:code:{code}:{roleId}
      → hasMenu(code): 检查菜单权限（递归解析父菜单）
          缓存 Key: SYS_CACHE:apiScope:menu:{code}:{roleId}
          管理员角色豁免
  → 通过 → 执行业务逻辑 / 拒绝 → 403
```

## 7. 关键设计模式

### 7.1 策略模式 — TokenGranter

4 种登录方式通过 `ITokenGranter` 接口统一，按 grantType 动态分发。

### 7.2 规则链模式 — OSS/SMS

OSS 和 SMS 提供商通过规则链 (Rule Chain) 选择：
```
PreOssRule → OssTemplateRule(选择提供商) → OssBuildRule → OssCacheRule → OssDataRule → FinallyOssRule
PreSmsRule → SmsBuildRule(选择提供商) → CacheSmsRule → FinallySmsRule
```

### 7.3 观察者模式 — 事件监听

```
EventPublisher → ApiLogEvent / ErrorLogEvent / UsualLogEvent
  → @Async @EventListener → LogListener → ILogService.saveLog()
```

### 7.4 拦截器模式 — MyBatis 插件

- `TenantInterceptor` → 自动追加 tenant_id 条件
- `DataScopeInterceptor` → 自动追加数据权限 WHERE 条件
- `PaginationInterceptor` → 分页处理

### 7.5 SPI 扩展 — LauncherService

`LauncherServiceImpl` 在启动阶段初始化配置。
