### 1.2 统一响应封装 `R<T>`

**来源**: `sources/bladex/bladex-tool/blade-core-tool/src/main/java/org/springblade/core/tool/api/R.java`

```java
public class R<T> implements Serializable {
    private int code;        // 状态码
    private boolean success; // 是否成功
    private T data;          // 承载数据（泛型）
    private String msg;      // 返回消息
}
```

**工厂方法**:
- `R.data(T)` — 成功返回，承载数据
- `R.data(T, String)` — 成功返回，承载数据 + 消息
- `R.status(boolean)` — 根据布尔值返回成功/失败
- `R.success(String)` — 成功消息
- `R.fail(String)` — 失败消息
- `R.fail(int, String)` — 失败状态码 + 消息

**使用模式**: 所有 Controller 返回值统一为 `R<T>` 或 `R<IPage<T>>` 或 `R<List<T>>`。导出接口（Excel）直接写 `HttpServletResponse` 无返回值。

### 2.1 核心调用链路

#### 链路 1：用户新增（User）

```
UserController.submit()
  → IUserService.submit(User)
    → UserServiceImpl.submit(User)
      → SysCache.getTenant(tenantId)        [缓存查询租户]
      → UserMapper.selectCount()            [校验账号数量/重复]
      → DigestUtil.encrypt(password)        [密码加密]
      → BaseServiceImpl.save(User)          [MyBatis-Plus 保存]
        → UserMapper.insert(User)
      → submitUserDept(User)
        → IUserDeptService.remove()         [删除旧关联]
        → IUserDeptService.saveBatch()      [批量保存部门关联]
      → CacheUtil.clear(USER_CACHE)         [清除缓存]
```

**源文件路径**:
- Controller: `modules/system/controller/UserController.java:143`
- Service 接口: `modules/system/service/IUserService.java:55`
- Service 实现: `modules/system/service/impl/UserServiceImpl.java:92`
- Mapper: `modules/system/mapper/UserMapper.java`

#### AOP 切面

BladeX 使用以下 AOP 机制：
- **权限切面**: `@PreAuthorize` / `@IsAdmin` / `@IsAdministrator` 注解驱动（在 bladex-tool 中实现）
- **租户切面**: `@NonDS` / `@TenantDS` 注解驱动数据源切换
- **XSS 过滤**: `@XssIgnore` 注解跳过 XSS 过滤
- **缓存切面**: `@Cacheable` Spring 原生缓存注解

### 2.3 Mapper 层分析

#### MyBatis-Plus 特性使用

- **BaseMapper**: 所有 Mapper 继承 `BaseMapper<Entity>`，获得标准 CRUD 方法
- **IService/BaseServiceImpl**: Service 层使用 MyBatis-Plus 的 `IService` / `BaseServiceImpl`
- **LambdaQueryWrapper**: 广泛使用 Lambda 方式构建查询条件
- **逻辑删除**: `@TableLogic` 注解标注 `isDeleted` 字段
- **雪花算法主键**: `@TableId(type = IdType.ASSIGN_ID)` 使用雪花算法生成 ID

#### 自定义 SQL（XML 映射）

每个 Mapper 都有对应的 XML 文件（与 Java 接口同目录），主要包含：
- 树形结构查询（tree/lazyTree）
- 角色菜单关联查询
- 多表联合查询
- 数据导出查询

#### 分页实现

使用 MyBatis-Plus 分页插件，通过 `Condition.getPage(Query)` 获取分页对象，`Query` 包含 `current` 和 `size` 参数。

## 第4章：安全与权限分析

### 4.1 认证链路

BladeX 使用自定义 OAuth2 认证体系：

```
客户端请求 → OAuth2 Filter (bladex-tool)
  → 解析 Token（Header: Authorization）
  → 提取 BladeUser 对象（userId, tenantId, roleId, deptId 等）
  → 注入到方法参数 @Param BladeUser user
```

**认证端点**:
- `/oauth/token` — OAuth2 Token 端点（由 bladex-tool 提供）
- `/oauth/sms/send-validate` — 短信验证码发送

**Token Granter（登录模式）**:
| Granter | type | 说明 |
|---------|------|------|
| `PasswordTokenGranter` | `password` | 标准密码模式（bladex-tool 提供） |
| `CaptchaTokenGranter` | `captcha` | 密码 + 验证码模式 |
| `SmsTokenGranter` | `sms` | 短信验证码模式 |
| `SocialTokenGranter` | `social` | 社交登录模式 |
| `RegisterTokenGranter` | `register` | 注册模式 |

**密码处理**: `BladePasswordHandler` — 使用 `DigestUtil.encrypt()` 加密（内部为 BCrypt）

**登录锁定**: `BladeLockHandler` — 登录失败次数限制，使用 Redis 存储

### 4.2 接口级权限

| 注解 | 含义 | 使用场景 |
|------|------|---------|
| `@IsAdmin` | 需要登录即可（任意登录用户） | 大部分业务接口 |
| `@IsAdministrator` | 需要超级管理员角色 | 租户管理、系统配置、代码生成 |
| `@PreAuth(menu = "xxx")` | 需要指定菜单权限 | 部门、字典、岗位、通知等 |
| `@PreAuth(AuthConstant.PERMIT_ALL)` | 允许所有人访问 | 下拉数据源接口 |

**注解分布统计**:
- 类级 `@IsAdmin`: 9 个 Controller
- 类级 `@IsAdministrator`: 8 个 Controller
- 类级 `@PreAuth`: 3 个 Controller
- 方法级 `@IsAdmin`: 6 个 Controller
- 方法级 `@IsAdministrator`: 3 个 Controller
- 方法级 `@PreAuth`: 4 个 Controller
- 无权限保护: 2 个 Controller（`WorkController`、`SearchController`、`LeaveController`）

### 4.3 租户隔离

**数据源注解**:
| 注解 | 含义 | 使用范围 |
|------|------|---------|
| `@NonDS` | 非租户数据源（使用默认数据源） | 90%+ 的 Controller |
| `@TenantDS` | 租户数据源（按租户隔离） | `NoticeController` |

**租户识别**: 从 `BladeUser.getTenantId()` 获取，由 OAuth2 Filter 注入

**租户隔离逻辑**: 在查询时手动添加 `.eq(Entity::getTenantId, bladeUser.getTenantId())` 条件（非自动注入）

**`@TenantIgnore` 豁免场景**: 在 bladex-tool 中实现，用于全局数据/系统级接口

### 4.4 输入校验

| 校验方式 | 使用情况 |
|---------|---------|
| `@Valid` + `@RequestBody` | 所有 POST 提交使用 |
| `@Validated` | `RoleServiceImpl` 类级使用 `@Validated` |
| 手动校验 | Service 层使用 `if (xxx == null) throw new ServiceException()` |
| XSS 防护 | `@XssIgnore` 用于通知提交、代码生成等富文本场景 |
| SM2 加密 | 短信发送时手机号使用 SM2 加密传输 |

### 4.5 数据级权限

- **部门数据隔离**: 非超管用户只能看到本级及以下部门数据
- **租户数据隔离**: 非超管用户只能看到本租户数据
- **角色权限递归**: 授予角色权限时，自动递归过滤子角色的无权菜单
