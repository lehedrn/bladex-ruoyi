## 第2章：配置文件与默认值

### 2.1 默认配置文件

| 配置文件 | 模块 | 内容 | 来源路径 |
|---------|------|------|---------|
| `blade-boot.yml` | blade-core-boot | Boot 默认配置 | `blade-core-boot/src/main/resources/blade-boot.yml` |
| `blade-mybatis.yml` | blade-starter-mybatis | MyBatis-Plus 默认配置（page-limit, overflow, tenant-mode, record-mode, batch-update-limit） | `blade-starter-mybatis/src/main/resources/blade-mybatis.yml` |
| `blade-transaction.yml` | blade-starter-transaction | Seata 事务默认配置 | `blade-starter-transaction/src/main/resources/blade-transaction.yml` |
| `blade-i18n.yml` | blade-starter-i18n | 国际化默认配置 | `blade-starter-i18n/src/main/resources/blade-i18n.yml` |
| `blade_rate_limiter.lua` | blade-starter-redis | Redis 限流 Lua 脚本 | `blade-starter-redis/src/main/resources/META-INF/scripts/blade_rate_limiter.lua` |

### 2.2 MyBatis-Plus 默认值

| 属性 | 默认值 | 说明 |
|------|--------|------|
| page-limit | 有默认最大限制 | 防止全量查询（AR-002） |
| overflow | 控制分页溢出行为 | |
| tenant-mode | 开启租户过滤 | 自动追加 WHERE tenant_id = ?（AR-018） |
| record-mode | 数据审计模式 | 数据变更记录 |
| batch-update-limit | 有默认限制 | 防止大批量数据变更（AR-019） |

### 2.3 条件装配默认行为

| 配置属性 | 默认值 | 装配行为 |
|---------|-------|---------|
| `swagger.enabled` | true（matchIfMissing） | false 时不注册 Swagger Bean |
| `blade.xss.enabled` | true（matchIfMissing） | false 时跳过 XSS 过滤 |
| `blade.api-crypto.enabled` | true（matchIfMissing） | false 时不注册加解密参数解析器 |
| `blade.i18n.enabled` | true（matchIfMissing） | false 时跳过国际化配置 |
| `report.enabled` | true（matchIfMissing） | false 时不注册 UReport Servlet |
| `blade.data-record.enabled` | true（matchIfMissing） | false 时跳过数据审计 |
| `blade.log.req-log.trace-log` | true（matchIfMissing） | false 时不注册 Trace Filter |
| `blade.sharding.enabled` | 无默认值 | false/未设置时不注册分片处理器 |
| `blade.tenant-dynamic.enabled` | 无默认值 | false/未设置时不注册动态数据源 |
| `blade.tenant-dynamic.global` | 无默认值 | false/未设置时跳过全局数据源拦截器 |

详见 `底层架构-分析报告.md` 第4.4节。

## 第3章：条件装配行为

### 3.1 装配顺序链

```
启动顺序（从高到低）：
1. BladeLaunchConfiguration        (HIGHEST_PRECEDENCE)
2. BladePropertyConfiguration      (HIGHEST_PRECEDENCE)
3. BladeContextAutoConfiguration   (HIGHEST_PRECEDENCE)
4. BladeWebMvcConfiguration        (HIGHEST_PRECEDENCE)
5. TransactionConfiguration        (HIGHEST_PRECEDENCE)
6. JacksonConfiguration            (before JacksonAutoConfiguration)
7. BladeRedisCacheAutoConfiguration(before JwtRedisConfiguration)
8. RedisTemplateConfiguration      (before JwtRedis/RedisAuto)
9. TenantConfiguration             (before MybatisPlusConfiguration)
10. DataRecordConfiguration         (before MybatisPlusConfiguration)
11. ShardingConfiguration           (before Druid/DynamicDataSource)
12. TenantDataSourceConfiguration   (before Druid/DynamicDataSource)
13. SwaggerAutoConfiguration        (before SpringDocConfiguration)
14. DruidMetricsConfiguration       (after MetricsAuto/DataSourceAuto)
```

详见 `底层架构-分析报告.md` 第1.4节。

### 3.2 条件注解类型

| 注解 | 使用场景 | 来源 |
|------|---------|------|
| `@ConditionalOnMissingBean` | 允许业务层覆盖默认实现 | 多个 Starter |
| `@ConditionalOnProperty` | 通过配置属性控制启用 | XSS、Swagger、API Crypto 等 |
| `@ConditionalOnWebApplication` | 仅在 Web 应用时装配 | Log、XSS |
| `@ConditionalOnClass` / `@ConditionalOnBean` | 依赖特定类/Bean 存在 | Metrics |
| `@AutoConfigureBefore` / `@AutoConfigureAfter` | 精确控制装配顺序 | 所有有顺序依赖的 Starter |
| `@AutoIgnore` | 跳过特定类的自动注册 | 编译期处理器支持 |

### 3.3 编译期自动装配生成

`blade-core-auto` 模块的 `AutoFactoriesProcessor` 在编译期：
- 扫描所有 `@AutoConfiguration` 注解（支持组合注解递归查找）
- 识别 `@Configuration`、`@Component`、`@Bean`、`@RestController` 等 Spring 注解
- 识别 `@FeignClient` 并注册到 `BladeFeignAutoConfiguration`
- 生成 `META-INF/spring.factories` 和 `META-INF/spring/.../AutoConfiguration.imports`
- 生成 `META-INF/spring-devtools.properties` 以支持热重载

详见 `底层架构-分析报告.md` 第1.1节。

## 第4章：配置加载机制

### 4.1 加载顺序

```
优先级（从高到低）：
1. 启动参数（--xxx=yyy）
2. 环境变量
3. application.yml
4. blade-*.yml（通过 @BladePropertySource 加载）
5. 代码默认值
```

### 4.2 @BladePropertySource 机制

`@BladePropertySource` 是 BladeX 自定义的配置文件加载注解，由 `BladePropertySourcePostProcessor` 在 Spring 启动时处理：

```
BladePropertySourcePostProcessor
  └── 读取 @BladePropertySource(value = "classpath:/blade-*.yml") 指定的文件
  └── 将其加载到 Spring Environment 中
```

### 4.3 多 Profile 差异

不同 Profile 下的配置差异主要体现在：

| Profile | 影响范围 |
|---------|---------|
| dev | 开发环境，开启 SQL 日志、关闭 XSS（可选） |
| test | 测试环境 |
| prod | 生产环境，开启所有安全防护 |

**关键差异点**：
- `swagger.enabled`：开发环境 true，生产环境通常 false
- `blade.xss.enabled`：默认 true（matchIfMissing），开发环境可能需要关闭
- `blade.log.req-log.trace-log`：默认 true，生产环境建议开启
- MyBatis 默认日志关闭（NoLoggingImpl），除非用户显式配置（AR-020）
