# 05_开发实践指南

> **分析日期**: 2026-05-21  
> **源文件路径**: sources/bladex/bladex-tool/, sources/bladex/bladex-boot/  
> **目的**: 总结 BladeX 框架中的设计模式应用、最佳实践与常见陷阱。

## 1. 设计模式应用

### 1.1 策略模式 — TokenGranter

**场景**: 不同登录方式（密码、验证码、短信、社交）使用不同的 Token 生成策略。

```
ITokenGranter (接口)
  ├── CaptchaTokenGranter   → grantType = "captcha"
  ├── PasswordTokenGranter  → grantType = "password"
  ├── SmsTokenGranter       → grantType = "sms_code"
  ├── SocialTokenGranter    → grantType = "social"
  └── RegisterTokenGranter  → grantType = "register"
```

- **代码来源**: bladex-boot/.../auth/granter/
- **优势**: 新增登录方式只需实现 `ITokenGranter` 接口并注册

### 1.2 模板方法模式 — BladeController

**场景**: 所有 Controller 继承 `BladeController`，统一数据返回格式。

```
BladeController (基类)
  ├── UserController
  ├── RoleController
  ├── MenuController
  └── ... (22个 Controller)
```

- **代码来源**: blade-core-boot/.../ctrl/BladeController.java
- **统一返回**: `R<T>` 类型，包含 code, data, msg, success

### 1.3 拦截器模式 — MyBatis 插件

**场景**: 数据权限、租户隔离通过 MyBatis 拦截器自动追加 SQL 条件。

```
MyBatis Interceptor Chain
  ├── TenantInterceptor    → 追加 tenant_id 条件
  ├── DataScopeInterceptor → 追加数据权限条件
  └── PaginationInterceptor → 分页处理
```

- **代码来源**: BladeScopeModelHandler + blade-starter-tenant

### 1.4 观察者模式 — 事件监听

**场景**: 操作日志、错误日志通过 Spring 事件异步记录。

```
EventPublisher → ApiLogEvent / ErrorLogEvent
  ├── ApiLogListener   → 异步写入 blade_log_api
  └── ErrorLogListener → 异步写入 blade_log_error
```

- **代码来源**: bladex-boot/.../event/

### 1.5 SPI 扩展模式 — LauncherService

**场景**: 各模块在 Spring 应用构建阶段介入配置。

```
LauncherService (接口, Ordered)
  ├── LogLauncherServiceImpl       → 日志模块配置
  ├── SwaggerLauncherServiceImpl   → API 文档配置
  ├── LiteFlowLauncherServiceImpl  → 规则引擎配置
  └── Log4j2LauncherServiceImpl    → Log4j2 配置
```

- **代码来源**: blade-core-launch/.../LauncherService.java
- **调用时机**: `BladeApplication` 启动时，构建 SpringApplicationBuilder 之前

### 1.6 工厂模式 — TokenGranterFactory

**场景**: 根据 grantType 动态获取对应的 TokenGranter 实现。

```
TokenGranterFactory.getTokenGranter(grantType) → ITokenGranter
```

## 2. 最佳实践

### 2.1 Service 层规范

```java
// 接口命名: I{Entity}Service
public interface IUserService extends IService<User> {
    UserInfo detail(Long userId);
    boolean grant(Long userId, String roleId);
}

// 实现命名: {Entity}ServiceImpl
@Service
public class UserServiceImpl extends ServiceImpl<UserMapper, User>
    implements IUserService {
    // ...
}
```

**要点**:
- 继承 `ServiceImpl<Mapper, Entity>` 获得 MyBatis-Plus 基础 CRUD
- 接口继承 `IService<Entity>` 获得 MyBatis-Plus 扩展方法
- 业务方法写在接口中，实现类中实现

### 2.2 Controller 层规范

```java
@RestController
@RequestMapping("/blade-system/user")
@RequiredArgsConstructor
public class UserController extends BladeController {

    private final IUserService userService;

    @GetMapping("/detail")
    public R<User> detail(@RequestParam Long id) {
        return R.data(userService.detail(id));
    }

    @PostMapping("/submit")
    public R submit(@Valid @RequestBody User user) {
        return status(userService.saveOrUpdate(user));
    }

    @PostMapping("/remove")
    public R remove(@RequestBody List<Long> ids) {
        return status(userService.deleteLogic(ids));
    }
}
```

**要点**:
- 继承 `BladeController` 获得统一返回和分页工具
- URL 遵循 `/blade-system/{resource}/{action}` 规范
- 新增/更新统一用 `/submit`，删除用 `/remove`
- 使用 `R.data()`, `status()` 方法构造返回值

### 2.3 缓存使用规范

```java
// 缓存读取
User user = UserCache.getUserById(userId);
if (user == null) {
    user = baseMapper.selectById(userId);
    if (user != null) {
        UserCache.setUser(userId, user);
    }
}

// 缓存清除 (数据变更后)
UserCache.remove(userId);
SysCache.clear();  // 全局清除 (角色授权时)
```

**要点**:
- 优先使用封装好的 Cache 类 (SysCache, UserCache, DictCache)
- 数据变更时必须清除相关缓存
- 角色授权后清除 SYS_CACHE 中的权限缓存

### 2.4 多租户开发规范

```java
// 查询自动带 tenant_id 条件 (租户拦截器)
List<User> users = userService.list();

// 不需要租户隔离的表使用 @NonDS 注解
@NonDS
public class DictServiceImpl { ... }
```

**要点**:
- 实体类包含 `tenant_id` 字段即可自动隔离
- 全局共享表（如字典）的 Service 标注 `@NonDS`
- 跨租户查询需要显式指定 tenantId

### 2.5 Wrapper 模式 (实体转 VO)

```java
// Wrapper 类: 负责 Entity → VO 转换 + 关联数据填充
public class UserWrapper extends BaseEntityWrapper<User, UserVO> {
    @Override
    public UserVO entityVO(User user) {
        UserVO userVO = Objects.requireNonNull(BeanUtil.copy(user, UserVO.class));
        // 填充关联数据
        userVO.setDeptName(SysCache.getDeptName(user.getDeptId()));
        userVO.setRoleName(SysCache.getRoleName(user.getRoleId()));
        return userVO;
    }
}
```

## 3. 常见陷阱

### 3.1 角色 ID 逗号分隔

**陷阱**: `blade_user.role_id` 是逗号分隔的字符串，不是关联表。

```java
// 错误: 尝试 JOIN 查询
// 正确: 先分割再查询
List<Long> roleIds = Func.toLongList(user.getRoleId());
List<Role> roles = roleService.listByIds(roleIds);
```

**影响**: 无法使用 SQL JOIN 做角色条件过滤，需要在应用层分割。

### 3.2 菜单非租户隔离

**陷阱**: `blade_menu` 表没有 `tenant_id` 字段，所有租户共享。

- 租户可用菜单由 `blade_tenant_package.menu_id` 控制
- 角色-菜单关联进一步限制

### 3.3 缓存不一致

**陷阱**: 角色授权后如果不清除 SYS_CACHE，权限验证仍使用旧缓存。

```java
// RoleService.grant() 中必须调用:
SysCache.clear();
// 或精确清除:
CacheUtil.clear(SYS_CACHE, "apiScope:code:*:" + roleId);
```

### 3.4 逻辑删除与唯一约束

**陷阱**: 逻辑删除的记录的唯一约束字段无法再次使用。

```
-- 如果 blade_user 有 UNIQUE(account)，
-- 删除后 (is_deleted=1)，新记录无法使用相同 account
-- 解决: 使用复合唯一索引 (account, is_deleted) 或在应用层处理
```

### 3.5 数据权限 scope_type 理解

| scope_type | 常见误解 | 实际行为 |
|-----------|---------|---------|
| 3 (本部门) | 包含子部门 | 仅本部门，不含子部门 |
| 4 (本部门及以下) | 仅直接子部门 | 所有子孙部门 (通过 ancestors) |
| 2 (自定义) | 固定部门列表 | 由 scope_value 动态决定 |

### 3.6 Token 中的 role_id

**陷阱**: JWT Token 中的 `role_id` 是逗号分隔字符串，解析时需分割。

```java
List<Long> roleIds = Func.toLongList(bladeUser.getRoleId());
```

## 4. 新增 Starter 模块指南

如需新增 `blade-starter-xxx` 模块：

1. **创建模块**: 在 bladex-tool 根 pom.xml 中添加 module
2. **编写 AutoConfiguration**:
   ```java
   @AutoConfiguration
   @ConditionalOnClass(XxxService.class)
   @EnableConfigurationProperties(XxxProperties.class)
   public class XxxAutoConfiguration {
       @Bean
       @ConditionalOnMissingBean
       public XxxService xxxService(XxxProperties properties) {
           return new XxxServiceImpl(properties);
       }
   }
   ```
3. **注册自动配置**: blade-core-auto 处理 (不需要 spring.factories)
4. **可选依赖**: 中间件 SDK 使用 `optional` 或 `provided`
5. **版本管理**: 在 blade-bom 中统一管理版本

## 5. 新增业务模块指南

在 bladex-boot 中新增业务模块：

1. **创建包结构**: `org.springblade.modules.{module}/`
2. **分层**:
   ```
   modules/{module}/
     ├── controller/    # Controller
     ├── service/       # Service 接口
     │   └── impl/      # Service 实现
     ├── entity/        # 实体类
     ├── mapper/        # Mapper 接口
     ├── wrapper/       # Entity → VO 转换
     └── vo/            # 视图对象
   ```
3. **注册 Swagger**: 在 `SwaggerConfiguration` 中添加 tag
4. **配置安全**: 在 `BladeConfiguration.secureRegistry()` 中添加跳过 URL（如有）
5. **Mapper XML**: 放在 `resources/mapper/{module}/` 目录
