# 01_系统架构分析文档

> **分析日期**: 2026-05-20  
> **源文件路径**: sources/bladex/bladex-tool/, sources/bladex/bladex-boot/  
> **核心结论**: BladeX 是一个高度模块化的企业级 Spring Boot 框架，采用"Core 核心层 + Starter 扩展层"双层架构，通过 SPI 机制、自动配置、多租户隔离实现企业级基础设施的统一封装。

---

## 1. 技术架构全景

### 1.1 架构分层

BladeX 框架采用五层架构设计：

| 层级 | 模块 | 职责 |
|------|------|------|
| **L5 聚合层** | blade-core-boot | 一键引入所有核心能力，快速启动 |
| **L4 服务治理层** | blade-core-cloud, blade-core-secure, blade-core-oauth2 | 微服务治理、安全认证、OAuth2 |
| **L3 数据与上下文层** | blade-core-db, blade-core-context | 数据库基础、请求上下文传递 |
| **L2 工具层** | blade-core-tool | 通用工具集、Jackson 扩展、加密 |
| **L1 基础设施层** | blade-core-launch, blade-core-auto | 启动配置、Undertow 替换、SPI 扩展 |

## 4. 核心业务流程时序图

### 4.1 用户登录流程

```
客户端 → CaptchaTokenGranter → BladeAuthorizationHandler → BladeUserDetailService
            → BladePasswordHandler → BladeTokenHandler → 返回 Token
```

**详细流程**:

1. 客户端 POST `/blade-auth/oauth/token`，携带 tenantId, username, password, grantType=captcha
2. `BladeAuthorizationHandler.preValidation()` 检查弱密码、账户锁定状态
3. `CaptchaTokenGranter.user()` 验证验证码（从 Redis），委托给 PasswordTokenGranter
4. `BladeUserDetailService.loadByUsername()` 按 (tenantId, username) 查询用户
5. `BladePasswordHandler.matches()` 比对密码明文（SM2 解密后）与存储哈希
6. `BladeAuthorizationHandler.authValidation()` 验证租户状态（存在、启用、未过期）
7. `BladeTokenHandler.enhance()` 生成 JWT access_token + refresh_token
8. `BladeAuthorizationHandler.authSuccessful()` 清除锁定计数

### 4.3 权限验证流程

```
请求到达 → SecureInterceptor
  → 跳过 URL 检查 (BladeConfiguration.secureRegistry)
  → Token 验证 (JWT 解码)
  → 提取 BladeUser
  → BladePermissionHandler
      → hasPermission(code) 检查 API 权限
      → hasMenu(code) 检查菜单访问
      → permissionAll() 检查路径权限
```

## 5. 关键设计模式

### 5.1 Starter 自动配置模式

每个 `blade-starter-*` 模块遵循标准 Spring Boot Starter 规范：
- 独立的 `pom.xml` 管理依赖
- `*AutoConfiguration` 类标注 `@AutoConfiguration`
- 通过 `blade-core-auto` 处理自动配置注册（替代 spring.factories）

### 5.2 LauncherService SPI 机制

`blade-core-launch` 定义了 `LauncherService` 接口，允许各模块在 Spring 应用构建阶段介入：

```java
public interface LauncherService extends Ordered {
    void launcher(SpringApplicationBuilder builder, String appName, String profile, boolean isLocalDev);
}
```

实现类：
- `LogLauncherServiceImpl` — 日志模块启动配置
- `LiteFlowLauncherServiceImpl` — 规则引擎启动配置
- `SwaggerLauncherServiceImpl` — API 文档启动配置
- `Log4j2LauncherServiceImpl` — Log4j2 启动配置

### 5.3 多租户架构

三层组合实现：
- `blade-starter-tenant` — 租户隔离（tenant_id 字段）
- `blade-starter-db-dynamic` — 运行时数据源切换
- `blade-starter-tenant-dynamic` — 分库 + 多租户

### 5.4 聚合模块模式

`blade-core-boot` 作为"全家桶"入口，依赖 9 个核心模块，业务项目只需引入一个依赖即可获得完整基础能力。

### 5.5 可选依赖模式

大量中间件使用 `optional` 或 `provided` 作用域，确保核心包轻量，用户按需引入具体实现。

## 7. 数据访问层设计

### 7.1 Service 层模式

```
Controller
  → Service 接口 (I{Entity}Service)
    → Service 实现 ({Entity}ServiceImpl extends ServiceImpl<Mapper, Entity>)
      → Mapper 接口 ({Entity}Mapper extends BaseMapper<Entity>)
        → Mapper XML ({Entity}Mapper.xml)
```

|--------|------|
