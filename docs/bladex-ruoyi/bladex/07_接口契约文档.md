## 第3章：数据结构对齐

### 3.1 统一响应体结构

| 维度 | 后端定义 | 前端处理 | 状态 |
|------|---------|---------|------|
| 响应体结构 | `R<T>` = `{code, success, data, msg}` | 响应拦截器不自动解包，直接返回原始响应 | ⚠️ 前端需手动访问 `response.data.data` |
| 成功码 | `code=200`（默认） | 拦截器判断 `status != 200` 弹窗 | ⚠️ HTTP 状态码与业务状态码混用 |
| 分页响应 | `R<IPage<T>>` = `{code, data: {records, total}}` | crud.js mixin 中使用 `data.total`, `data.records` | ✅ |
| 失败响应 | `R.fail(msg)` = `{code, success:false, msg}` | 拦截器统一 `ElMessage.error(msg)` | ✅ |

### 3.2 分页参数对齐

| 维度 | 后端定义 | 前端定义 | 状态 |
|------|---------|---------|------|
| 当前页参数名 | `current` | `current` | ✅ |
| 每页大小参数名 | `size` | `size` | ✅ |
| 默认每页大小 | 10 | 10 | ✅ |
| 分页返回总数字段 | `total` | `data.total` | ✅ |
| 分页返回数据字段 | `records` | `data.records` | ✅ |

### 3.3 用户字段对齐

| 字段 | 后端类型（User.java） | 前端提交 | 状态 | 说明 |
|------|---------------------|---------|------|------|
| account | String | 表单输入 | ✅ | |
| password | String | SM2 加密后传输 | ✅ | 后端 BCrypt 存储 |
| realName | String | 表单输入 | ✅ | |
| phone | String | SM2 加密传输 | ✅ | |
| email | String | 表单输入 | ✅ | |
| roleId | String | 逗号拼接多值 | ✅ | |
| deptId | String | 逗号拼接多值 | ✅ | |
| postId | String | 逗号拼接多值 | ✅ | |
| tenantId | String | 从 Store 获取 | ✅ | |

## 第4章：错误码映射

### 4.1 后端错误码体系

| 错误码范围 | 含义 | 来源 |
|-----------|------|------|
| 200 | 业务成功 | R.data() |
| 400 | 请求参数错误 | R.fail(400, msg) |
| 401 | 未认证/Token 过期 | TokenInterceptor |
| 403 | 权限不足 | AuthAspect |
| >2000 | OAuth2 专用错误 | OAuth2ExceptionHandler |

### 4.2 前端错误处理映射

| 前端拦截条件 | 处理行为 | 说明 |
|------------|---------|------|
| 白名单状态码 | 直接 reject | 由调用方处理 |
| 401 (首次) | 触发 Token 刷新 | 自动重试原请求 |
| 401 (已重试) | 清除 Token，跳转登录 | 刷新失败 |
| >2000 | 显示 error_description | OAuth2 错误优先 |
| !=200 | ElMessage.error(msg) | 一般业务错误 |

### 4.3 后端错误消息

后端使用硬编码中文错误消息，示例：

| Service | 错误消息 | 来源 |
|---------|---------|------|
| UserServiceImpl | "当前租户已到最大账号额度!" | 后端报告 5.2 |
| UserServiceImpl | "当前用户 [{}] 已存在!" | 后端报告 5.2 |
| UserServiceImpl | "不能删除本账号!" | 后端报告 5.2 |
| UserServiceImpl | "原密码不正确!" | 后端报告 5.2 |
| RoleServiceImpl | "无权配置超管角色!" | 后端报告 5.2 |
| RoleServiceImpl | "请先删除子节点!" | 后端报告 5.2 |
| MenuServiceImpl | "菜单名或编号已存在!" | 后端报告 5.2 |
| MenuServiceImpl | "菜单路径已存在!" | 后端报告 5.2 |

> **注意**：后端未实现国际化（i18n），所有错误消息均为硬编码中文。

## 第5章：业务规则一致性

详见 `04_业务逻辑公式手册.md` 第7章「规则交叉验证」。

### 5.1 一致性总结

| 验证维度 | 结果 |
|---------|------|
| 约束规则对齐 | 密码加密/账号唯一/手机号唯一/分页默认值均一致 |
| 权限规则对齐 | 登录认证/按钮权限/菜单权限/审核操作均一致 |
| 计算规则对齐 | Token 生成/OSS 文件名由后端独控，无前端计算 |
| 异常规则对齐 | Token 过期/全局错误/OAuth2 错误/错误日志均一致 |
| 差异项 | 邮箱/身份证/姓名仅前端有格式校验；锁屏保护仅前端实现 |
