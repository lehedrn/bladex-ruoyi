## 第1章：入口点分析

### 1.1 自动装配机制

BladeX 使用**自定义注解处理器**（`blade-core-auto` 模块）在**编译期**自动生成 Spring Boot 自动装配元数据，而非手动编写 `spring.factories` 或 `AutoConfiguration.imports` 文件。这是 BladeX 区别于标准 Spring Boot 项目的核心架构特征。

#### 核心入口处理器

| 入口类型 | 文件路径 | 触发的装配内容 | 被谁引入/依赖 |
|---------|---------|--------------|-------------|
| SPI 服务处理器 | `blade-core-auto/.../AutoServiceProcessor.java` | 扫描 `@AutoService` 注解，生成 `META-INF/services/` SPI 文件 | 编译期注解处理器 |
| 自动配置处理器 | `blade-core-auto/.../AutoFactoriesProcessor.java` | 扫描 `@AutoConfiguration`、`@Configuration`、`@FeignClient` 等，生成 `spring.factories` 和 `AutoConfiguration.imports` | 编译期注解处理器 |

**AutoFactoriesProcessor 工作原理**：
- 来源：`/home/workspace/com/bladex-ruoyi/sources/bladex/bladex-tool/blade-core-auto/src/main/java/org/springblade/core/auto/factories/AutoFactoriesProcessor.java`
- 扫描所有类，识别 `@AutoConfiguration` 注解（支持组合注解递归查找）
- 识别 `@Configuration`、`@Component`、`@Bean`、`@RestController` 等 Spring 注解
- 识别 `@FeignClient` 并注册到 `BladeFeignAutoConfiguration` 的 factories key
- 编译期生成 `META-INF/spring.factories` 和 `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports`
- 同时生成 `META-INF/spring-devtools.properties` 以支持热重载
- 支持 `@AutoIgnore` 跳过特定类的自动注册

### 2.4 基础设施能力

#### 数据源能力
- **动态数据源路由**：基于 `@TenantDS` / `@ShardingDS` 注解实现运行时数据源切换
- **租户数据源隔离**：`blade-starter-tenant-dynamic` 提供租户级别数据源自动创建与切换
- **分库分表**：`blade-starter-sharding` 集成 ShardingSphere 实现分片

#### 安全能力
- **认证过滤器链**：`blade-core-secure` 提供 Basic/Token/Sign/Client 四类拦截器
- **权限校验**：`@PreAuth` 注解 + `AuthAspect` AOP 切面
- **Nonce 防重放**：`NonceStore` 接口 + `LocalNonceStore` 实现

#### 租户能力
- **SQL 级租户过滤**：基于 MyBatis-Plus `TenantLineInnerInterceptor`
- **租户上下文传播**：`BladeContext` 在请求生命周期中持有租户 ID
- **异步租户传播**：`@TenantAsync` 注解 + `BladeTenantAsyncAspect` 确保异步线程租户上下文不丢失
- **租户忽略**：`@TenantIgnore` 注解跳过特定方法的租户过滤

#### 缓存能力
- **多序列化策略**：JSON / ProtoStuff 可配置
- **分布式锁**：`BladeLockAutoConfiguration` 提供 Redis 分布式锁
- **限流器**：`RateLimiterAutoConfiguration` + Lua 脚本实现滑动窗口限流
- **Pub/Sub**：`RedisPubSubConfiguration` 提供发布订阅封装
- **Stream**：`RedisStreamConfiguration` 提供 Stream 消费封装
- **防抖**：`BladeDebounceAutoConfiguration` 方法级防抖

### 4.3 配置加载机制

`@BladePropertySource` 是 BladeX 自定义的配置文件加载注解，由 `BladePropertySourcePostProcessor` 在 Spring 启动时处理：


## 关键发现与架构评价

### 1. 编译期自动装配生成

BladeX 最大架构特色是 `blade-core-auto` 模块——一个**编译期注解处理器**，它在编译阶段自动扫描所有 `@AutoConfiguration`、`@Configuration` 等注解，生成 `spring.factories` 和 `AutoConfiguration.imports` 文件。这使得开发者**无需手动维护自动装配元数据**，降低了 starter 开发门槛。

### 2. 条件装配链的精确控制

大量使用 `@ConditionalOnMissingBean` 和 `@AutoConfigureBefore/After` 确保 Bean 注册顺序正确，同时允许业务层通过提供自定义 Bean 覆盖默认实现。这种设计遵循了 Spring Boot 的 "约定优于配置" 理念。

### 3. 租户隔离的多层实现

租户隔离在三个层次实现：
- **SQL 层**：`TenantLineInnerInterceptor` 自动追加 `WHERE tenant_id = ?`
- **数据源层**：`blade-starter-tenant-dynamic` 支持租户级别数据源动态切换
- **对象存储层**：`BladeOssRule` 按租户隔离文件路径

### 4. 工具类库的完备性

`blade-core-tool` 提供了 40+ 工具类，覆盖了字符串、日期、加密、序列化、反射等日常开发所需的基础操作，减少了外部依赖引入。

### 5. 【异常/幻觉警告区】
