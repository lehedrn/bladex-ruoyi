# RuoYi-Vue3 后端业务层分析报告

## 概述

RuoYi-Vue3 基于 Spring Boot 3.x + Spring Security + MyBatis + Redis 技术栈，采用经典三层架构（Controller → Service → Mapper），实现了完整的 RBAC 权限管理体系。

**核心模块结构：**
- `ruoyi-admin`：Controller 层，处理 HTTP 请求
- `ruoyi-system`：Service + Mapper 层，业务逻辑与数据访问
- `ruoyi-common`：公共模块，包含实体类、工具类、常量等
- `ruoyi-framework`：框架层，包含认证、Token、权限服务等

## 2. 核心调用链

### 2.1 用户模块调用链

```
SysUserController (ruoyi-admin)
  ├── ISysUserService (接口)
  │     └── SysUserServiceImpl (ruoyi-system/service/impl)
  │           ├── SysUserMapper (ruoyi-system/mapper) → MyBatis XML
  │           ├── SysUserRoleMapper → sys_user_role 表操作
  │           ├── SysUserPostMapper → sys_user_post 表操作
  │           ├── SysRoleMapper → 查询用户角色
  │           ├── SysPostMapper → 查询用户岗位
  │           ├── ISysConfigService → 获取初始密码配置
  │           └── ISysDeptService → 部门数据权限校验
  └── 直接依赖的 Service
        ├── ISysRoleService → 角色选择、授权
        ├── ISysDeptService → 部门树、数据权限
        └── ISysPostService → 岗位选择
```

**关键方法追踪：**

| Controller 方法 | Service 方法 | Mapper 方法 |
|----------------|-------------|-------------|
| `list()` | `selectUserList()` [@DataScope] | `selectUserList()` |
| `add()` | `insertUser()` [@Transactional] | `insertUser()` + `batchUserRole()` + `batchUserPost()` |
| `edit()` | `updateUser()` [@Transactional] | `deleteUserRoleByUserId()` + `insertUserRole()` + `deleteUserPostByUserId()` + `insertUserPost()` + `updateUser()` |
| `remove()` | `deleteUserByIds()` [@Transactional] | `deleteUserRole()` + `deleteUserPost()` + `deleteUserByIds()` |
| `resetPwd()` | `resetPwd()` | `resetUserPwd()` |
| `changeStatus()` | `updateUserStatus()` | `updateUserStatus()` |
| `authRole()` | `insertUserAuth()` [@Transactional] | `deleteUserRoleByUserId()` + `batchUserRole()` |

## 4. 认证与授权流程

### 4.1 登录流程

```
POST /login
  │
  ▼
SysLoginController.login()
  │
  ▼
SysLoginService.login(username, password, code, uuid)
  │
  ├── 1. validateCaptcha() ─── 校验验证码
  │     ├── configService.selectCaptchaEnabled() ─── 检查是否开启验证码
  │     ├── redisCache.getCacheObject(CAPTCHA_CODE_KEY + uuid) ─── 从 Redis 获取验证码
  │     └── 校验失败则 AsyncManager 记录登录失败日志
  │
  ├── 2. loginPreCheck() ─── 登录前置校验
  │     ├── 用户名/密码非空检查
  │     ├── 密码长度检查 (5-20字符)
  │     ├── 用户名长度检查 (2-20字符)
  │     └── IP黑名单检查 (sys.login.blackIPList)
  │
  ├── 3. AuthenticationManager.authenticate()
  │     └── UserDetailsServiceImpl.loadUserByUsername()
  │           ├── userService.selectUserByUserName() ─── 查询用户
  │           ├── 检查 delFlag (是否已删除)
  │           ├── 检查 status (是否已停用)
  │           ├── SysPasswordService.validate() ─── 密码重试次数检查
  │           │     ├── Redis 获取重试次数 (PWD_ERR_CNT_KEY + username)
  │           │     ├── 超过 maxRetryCount 则抛出 UserPasswordRetryLimitExceedException
  │           │     └── 密码匹配失败则递增计数并缓存
  │           └── createLoginUser() ─── 构造 LoginUser
  │                 └── SysPermissionService.getMenuPermission() ─── 加载菜单权限
  │
  ├── 4. AsyncManager.recordLogininfor() ─── 异步记录登录成功日志
  │
  ├── 5. recordLoginInfo(userId) ─── 更新登录 IP 和时间
  │     └── userService.updateLoginInfo()
  │
  └── 6. TokenService.createToken(loginUser) ─── 生成 Token
        ├── 生成 UUID token
        ├── setUserAgent() ─── 记录 IP、浏览器、操作系统
        ├── refreshToken() ─── 写入 Redis (LOGIN_TOKEN_KEY + uuid, expireTime=30min)
        └── Jwts.builder() ─── 生成 JWT (HS512签名, 包含 LOGIN_USER_KEY 和 username)
```

### 4.2 Token 验证流程

```
HTTP 请求 (携带 Authorization: Bearer <JWT>)
  │
  ▼
JwtAuthenticationTokenFilter.doFilterInternal()
  │
  ▼
TokenService.getLoginUser(request)
  ├── 从 Header 提取 JWT Token
  ├── parseToken() ─── 解析 JWT (验证签名、提取 uuid)
  └── redisCache.getCacheObject(LOGIN_TOKEN_KEY + uuid) ─── 从 Redis 获取 LoginUser
  │
  ▼
verifyToken() ─── 验证 Token 有效期
  └── 剩余不足 20 分钟自动刷新 Redis 缓存
  │
  ▼
SecurityContextHolder.setAuthentication() ─── 设置 Spring Security 上下文
```

**Token 设计特点：**
- JWT 仅作为签名验证（防止篡改），不包含用户信息
- 用户数据完全存储在 Redis 中（可实时失效）
- 有效期：默认 30 分钟，不足 20 分钟自动续期
- 强制退出：直接从 Redis 删除 key 即可

### 4.3 权限验证机制

**权限注解：** `@PreAuthorize("@ss.hasPermi('system:user:list')")`
- `@ss` 是 Spring 注册的 `PermissionService` Bean
- 检查当前用户的 `permissions` 集合是否包含指定权限字符串

**数据权限：** `@DataScope(deptAlias = "d", userAlias = "u")`
- AOP 拦截器，根据角色的 `dataScope` 字段自动拼接 SQL 过滤条件
- 5种数据范围：
  1. 全部数据权限
  2. 自定义数据权限（通过 sys_role_dept 配置）
  3. 本部门数据权限
  4. 本部门及以下数据权限
  5. 仅本人数据权限

### 4.4 注册流程

```
POST /register
  │
  ▼
SysRegisterController.register()
  │
  ├── 检查 sys.account.registerUser 配置是否开启注册
  │
  ▼
SysRegisterService.register()
  │
  ├── validateCaptcha() ─── 验证码校验
  ├── 用户名/密码格式校验
  ├── userService.checkUserNameUnique() ─── 用户名唯一性检查
  ├── userService.registerUser() ─── 注册用户（仅插入用户表，不关联角色/岗位）
  └── AsyncManager.recordLogininfor() ─── 记录注册日志
```

## 7. 架构特点总结

### 7.1 技术栈

- **Spring Boot 3.x** + **Spring Security** + **MyBatis**
- **Redis** 用于 Token 存储、配置/字典缓存、验证码、防重提交
- **JWT** 用于 Token 签名验证（用户数据存储在 Redis）
- **Kaptcha** 用于验证码生成（支持算术/字符两种模式）
- **Apache POI** 用于 Excel 导入导出
- **Swagger/OpenAPI 3** 用于 API 文档

### 7.2 设计模式

| 模式 | 应用 |
|-----|------|
| 三层架构 | Controller → Service → Mapper |
| RBAC | 用户-角色-菜单-部门（数据权限） |
| 策略模式 | 数据权限（5种范围策略） |
| 观察者模式 | 异步日志记录（AsyncManager） |
| 工厂模式 | 异步任务工厂（AsyncFactory） |
| 模板方法 | BaseController 提供通用方法 |
| 缓存模式 | Read-through Cache（参数、字典） |

### 7.3 安全机制

| 机制 | 实现 |
|-----|------|
| 认证 | Spring Security + JWT + Redis |
| 授权 | @PreAuthorize + PermissionService |
| 数据权限 | @DataScope AOP 切面 |
| 密码安全 | BCrypt 加密 + 重试限制 + 过期策略 |
| XSS 防护 | @Xss 注解 + 过滤器 |
| 验证码 | Kaptcha（可配置开关） |
| IP 黑名单 | 配置项 `sys.login.blackIPList` |
| 防重提交 | Redis 缓存标记 |
| 接口限流 | Redis 计数 |

### 7.4 事务管理

**@Transactional 使用场景：**
- 用户新增/修改/删除（同时操作用户表、用户角色关联表、用户岗位关联表）
- 角色新增/修改/删除（同时操作角色表、角色菜单关联表、角色部门关联表）
- 菜单排序批量更新
- 字典类型修改（同时更新关联字典数据的类型）
