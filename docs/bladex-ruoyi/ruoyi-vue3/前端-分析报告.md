## 四、路由与权限流程

### 4.1 路由表结构

**来源文件：** `/home/workspace/com/bladex-ruoyi/sources/ruoyi/ruoyi-vue3/ruoyi-ui/src/router/index.js`

路由分为两类：

#### 公共路由（constantRoutes）

不依赖后端，启动即注册：

| 路径 | 组件 | 说明 |
|------|------|------|
| `/redirect/:path` | redirect/index | 重定向中转（刷新用） |
| `/login` | login | 登录页 |
| `/register` | register | 注册页 |
| `/:pathMatch(.*)*` | error/404 | 404 兜底 |
| `/401` | error/401 | 401 错误页 |
| `/` → `/index` | index | 首页（affix=true） |
| `/lock` | lock | 锁屏页 |
| `/user/profile/:activeTab?` | profile | 个人中心 |

#### 动态路由（dynamicRoutes）

按权限过滤后注册：

| 路径 | 权限要求 | 功能 |
|------|----------|------|
| `/system/user-auth/role/:userId` | `system:user:edit` | 用户分配角色 |
| `/system/role-auth/user/:roleId` | `system:role:edit` | 角色分配用户 |
| `/system/dict-data/index/:dictId` | `system:dict:list` | 字典数据 |
| `/monitor/job-log/index/:jobId` | `monitor:job:list` | 调度日志 |
| `/tool/gen-edit/index/:tableId` | `tool:gen:edit` | 编辑代码生成配置 |

### 4.2 路由守卫流程

**来源文件：** `/home/workspace/com/bladex-ruoyi/sources/ruoyi/ruoyi-vue3/ruoyi-ui/src/permission.js`

```
router.beforeEach(to, from):
│
├── NProgress.start()
├── 有 Token?
│   ├── YES
│   │   ├── 设置页面标题 (setTitle)
│   │   ├── 目标 /login → 重定向 /
│   │   ├── 在白名单中 → 放行
│   │   ├── 已锁屏且目标不是 /lock → 重定向 /lock
│   │   ├── 未锁屏且目标是 /lock → 重定向 /
│   │   ├── roles 为空？(首次访问)
│   │   │   ├── isRelogin.show = true (防止重复弹窗)
│   │   │   ├── getInfo() 获取用户信息
│   │   │   ├── generateRoutes() 从后端获取路由并生成
│   │   │   ├── router.addRoute() 注册动态路由
│   │   │   └── return { ...to, replace: true } (重新导航)
│   │   └── roles 非空 → 放行
│   └── NO
│       ├── 在白名单中 → 放行
│       └── 重定向 /login?redirect=原路径
│
└── router.afterEach() → NProgress.done()
```

**白名单：** `['/login', '/register']`

### 4.3 动态路由加载流程

**来源文件：** `/home/workspace/com/bladex-ruoyi/sources/ruoyi/ruoyi-vue3/ruoyi-ui/src/store/modules/permission.js`

```
generateRoutes():
│
├── getRouters() → GET /getRouters (后端返回路由树)
│
├── 三份深拷贝：sdata / rdata / defaultData
│
├── filterAsyncRouter(sdata) → sidebarRoutes (侧边栏菜单)
│   ├── component === 'Layout' → 替换为 Layout 组件
│   ├── component === 'ParentView' → 替换为 ParentView
│   ├── component === 'InnerLink' → 替换为 InnerLink
│   └── 其他 → loadView() 动态加载 Vue 组件
│
├── filterAsyncRouter(rdata, false, true) → rewriteRoutes (带children处理)
│
├── filterAsyncRouter(defaultData) → defaultRoutes
│
├── filterDynamicRoutes(dynamicRoutes) → 过滤前端定义的路由
│   └── 按 permissions/roles 验证，通过后 addRoute() 注册
│
├── setRoutes(rewriteRoutes)
├── setSidebarRouters(constantRoutes.concat(sidebarRoutes))
└── setTopbarRoutes(defaultRoutes)
```

`loadView()` 使用 `import.meta.glob('./../../views/**/*.vue')` 预加载所有 views 下的 .vue 文件，通过路径匹配返回对应的异步组件加载函数。

## 八、前端权限实现

### 8.1 权限体系总览

RuoYi-Vue3 使用三层权限控制：

| 层级 | 机制 | 说明 |
|------|------|------|
| 路由级 | 后端返回路由树 + 前端 addRoute | 无权限的路由不注册，页面不可访问 |
| 菜单级 | Sidebar 渲染 permissionStore.sidebarRouters | 无权限菜单不显示 |
| 按钮级 | v-hasPermi / v-hasRole 指令 | 无权限按钮从 DOM 中移除 |

### 8.2 v-hasPermi 指令

**来源文件：** `/home/workspace/com/bladex-ruoyi/sources/ruoyi/ruoyi-vue3/ruoyi-ui/src/directive/permission/hasPermi.js`

```js
mounted(el, binding) {
  const all_permission = "*:*:*"
  const permissions = useUserStore().permissions
  const permissionFlag = binding.value // 数组，如 ['system:user:add']
  const hasPermissions = permissions.some(p =>
    all_permission === p || permissionFlag.includes(p)
  )
  if (!hasPermissions) {
    el.parentNode && el.parentNode.removeChild(el)
  }
}
```

**全通标识：** `"*:*:*"` -- 拥有此标识则放行所有权限检查。

**使用示例：**
```html
<el-button v-hasPermi="['system:user:add']">新增</el-button>
<el-button v-hasPermi="['system:user:edit']">修改</el-button>
<el-button v-hasPermi="['system:user:remove']">删除</el-button>
```

### 8.3 v-hasRole 指令

**来源文件：** `/home/workspace/com/bladex-ruoyi/sources/ruoyi/ruoyi-vue3/ruoyi-ui/src/directive/permission/hasRole.js`

```js
mounted(el, binding) {
  const super_admin = "admin"
  const roles = useUserStore().roles
  const roleFlag = binding.value
  const hasRole = roles.some(role =>
    super_admin === role || roleFlag.includes(role)
  )
  if (!hasRole) {
    el.parentNode && el.parentNode.removeChild(el)
  }
}
```

**超级管理员：** `"admin"` -- 拥有 admin 角色则放行所有角色检查。

### 8.4 编程式权限验证

**来源文件：** `/home/workspace/com/bladex-ruoyi/sources/ruoyi/ruoyi-vue3/ruoyi-ui/src/plugins/auth.js`

| 方法 | 说明 |
|------|------|
| `$auth.hasPermi('system:user:add')` | 是否具备单个权限 |

## 九、关键设计模式总结

### 9.1 组件化模式

1. **全局注册通用组件**：在 main.js 中 `app.component()` 注册，模板中直接使用无需 import
2. **布局-页面分层**：Layout 提供骨架，Views 填充内容，AppMain 负责 keep-alive 缓存
3. **CRUD 标准模板**：查询表单 + 操作按钮行 + el-table + Pagination + el-dialog 表单

### 9.2 状态管理模式

1. **Pinia Composition API**：所有 Store 使用 `defineStore` + setup 语法
2. **持久化策略**：Cookie（sidebarStatus/size/token）+ localStorage（settings/lock/tagsView）
3. **字典缓存**：dictStore 内存缓存 + useDict() 延迟加载

### 9.3 权限控制模式

1. **路由级**：后端返回菜单树 → 前端转为路由配置 → addRoute() 动态注册
2. **菜单级**：Sidebar 从 permissionStore 读取过滤后的路由树渲染
3. **按钮级**：v-hasPermi 指令在 mounted 时验证，无权限直接移除 DOM
4. **编程式**：$auth 对象提供 hasPermi/hasRole 方法供 JS 逻辑使用

### 9.4 HTTP 通信模式

1. **统一 baseURL**：通过环境变量 VITE_APP_BASE_API 配置
2. **Token 自动注入**：请求拦截器自动添加 Authorization header
3. **统一错误处理**：响应拦截器按 code 分类处理（401 弹窗、500 消息、601 警告）
4. **防重复提交**：sessionStorage 记录请求指纹，间隔时间内拒绝
5. **通用下载**：download() 方法封装 blob 处理 + loading + 错误提示

### 9.5 页面刷新机制

通过 `/redirect/:path` 路由实现：
1. `$tab.refreshPage()` → TagsViewStore.delCachedView()
2. `router.replace('/redirect' + path + query)`
3. 进入 redirect/index.vue
4. 立即 `router.replace({ path: originalPath, query })`
5. 组件重新挂载，keep-alive 缓存已清除
