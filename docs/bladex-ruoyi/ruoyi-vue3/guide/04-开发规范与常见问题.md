# 开发规范与常见问题

---

## 1. 代码风格

### 1.1 Java 编码规范

- **JDK 版本**: 17+
- **编码**: UTF-8
- **缩进**: 4 空格
- **最大行宽**: 120 字符
- **类名**: `PascalCase`（如 `SysUserServiceImpl`）
- **方法名**: `camelCase`（如 `selectUserList`）
- **常量**: `UPPER_SNAKE_CASE`（如 `Constants.SUCCESS`）
- **包名**: 全小写（如 `com.ruoyi.system.service`）

### 1.2 Controller 层规范

```java
@RestController
@RequestMapping("/system/user")
public class SysUserController extends BaseController {

    @Autowired
    private ISysUserService userService;

    @PreAuthorize("@ss.hasPermi('system:user:list')")
    @GetMapping("/list")
    public TableDataInfo list(SysUser user) {
        startPage();
        List<SysUser> list = userService.selectUserList(user);
        return getDataTable(list);
    }
}
```

**关键约定**：
- 所有 Controller 继承 `BaseController`，获得 `startPage()`、`getDataTable()`、`toAjax()` 等方法
- 使用 `@PreAuthorize` 进行权限控制
- 列表接口必须调用 `startPage()` 实现分页
- 返回统一使用 `AjaxResult` 或 `TableDataInfo`

### 1.3 Service 层规范

**接口命名**: `ISysXxxService`
**实现命名**: `SysXxxServiceImpl`

```java
@Service
public class SysUserServiceImpl implements ISysUserService {
    @Autowired
    private SysUserMapper userMapper;

    @Override
    @DataScope(deptAlias = "d", userAlias = "u")
    public List<SysUser> selectUserList(SysUser user) {
        return userMapper.selectUserList(user);
    }
}
```

**关键约定**：
- 需要数据权限的方法加 `@DataScope` 注解
- 需要记录操作日志的方法在 Controller 层加 `@Log` 注解
- 异常使用自定义 `ServiceException`（继承自 `RuntimeException`）

### 1.4 Mapper 层规范

```java
public interface SysUserMapper {
    public List<SysUser> selectUserList(SysUser user);
    public SysUser selectUserById(Long userId);
    public int insertUser(SysUser user);
    public int updateUser(SysUser user);
    public int deleteUserById(Long userId);
}
```

- Mapper 接口放在 `mapper/` 目录
- XML 文件放在 `resources/mapper/` 目录
- XML 的 `namespace` 必须对应 Mapper 接口的全限定类名

### 1.5 前端编码规范

**文件命名**: `kebab-case`（如 `user-info.vue`）

**组件命名**: `PascalCase`（如 `<el-table>`、`<DictTag>`）

**API 调用**:

```javascript
import request from '@/utils/request'

// 查询用户列表
export function listUser(query) {
  return request({
    url: '/system/user/list',
    method: 'get',
    params: query
  })
}

// 新增用户
export function addUser(data) {
  return request({
    url: '/system/user',
    method: 'post',
    data: data
  })
}
```

## 2. 命名规范

### 2.1 数据库命名

- **表名**: `sys_xxx`（系统表）、`biz_xxx`（业务表）
- **字段名**: `snake_case`
- **主键**: `{table}_id`（如 `user_id`）
- **外键**: `{ref_table}_id`（如 `dept_id`）
- **状态字段**: `status`（CHAR(1)，0正常 1停用）
- **删除标记**: `del_flag`（CHAR(1)，0存在 2删除）

### 2.2 权限标识命名

格式: `{模块}:{功能}:{操作}`

```
system:user:list        # 用户列表
system:user:add         # 新增用户
system:user:edit        # 修改用户
system:user:remove      # 删除用户
system:user:query       # 查询用户详情
system:user:export      # 导出用户
system:user:import      # 导入用户
system:user:resetPwd    # 重置密码
```

操作动词约定：`list`（列表）、`query`（详情）、`add`（新增）、`edit`（修改）、`remove`（删除）、`export`（导出）、`import`（导入）。

### 2.3 字典命名

- **字典类型**: `sys_xxx`（如 `sys_user_sex`、`sys_normal_disable`）
- **字典数据**: 标签用中文，值用数字或字符串（如 `0`/`1`、`00`/`01`）

## 3. 版本控制流程

### 3.1 分支策略

```
main          ← 稳定发布分支
├── develop   ← 开发集成分支
│   ├── feature/xxx  ← 功能分支
│   ├── feature/yyy  ← 功能分支
│   └── fix/zzz      ← 修复分支
```

### 3.2 Commit Message 格式

遵循 Conventional Commits 规范：

```
<type>(<scope>): <subject>

<body>

<footer>
```

**Type 取值**：

| type | 说明 |
|------|------|
| feat | 新功能 |
| fix | Bug 修复 |
| docs | 文档变更 |
| style | 代码格式（不影响功能） |
| refactor | 重构 |
| perf | 性能优化 |
| test | 测试相关 |
| chore | 构建/工具链变更 |

**示例**：

```
feat(user): 新增用户导入导出功能

支持 Excel 格式导入导出，使用 Apache POI 实现

Closes #123
```

### 3.3 代码审查

- 功能分支完成后向 `develop` 提交 Merge Request
- 至少 1 人 Review 通过后方可合入
- 合入前确保编译通过、测试通过

## 5. 常见问题解决方案

### 5.1 环境配置问题

#### Q: 启动报错 `Cannot determine embedded database driver class`

**原因**: 数据源配置未正确加载。

**解决**:
1. 检查 `application-druid.yml` 中的数据库 URL、用户名、密码是否正确
2. 确认 `application.yml` 中 `spring.profiles.active: druid`
3. 确认 `pom.xml` 中 MySQL 依赖已引入

#### Q: Redis 连接失败 `Unable to connect to Redis`

**原因**: Redis 未启动或配置错误。

**解决**:
```bash
# 检查 Redis 是否运行
redis-cli ping

# 检查 application.yml 中的 Redis 配置
# spring.data.redis.host / port / password / database
```

#### Q: 前端访问后端接口 404

**原因**: 前端代理配置或后端 Context Path 不匹配。

**解决**:
1. 检查 `vite.config.js` 中的代理配置：`/dev-api` → `http://localhost:8080`
2. 确认前端请求路径以 `/dev-api` 开头
3. 确认后端 `server.servlet.context-path: /`

### 5.2 数据库问题

#### Q: 分页查询不生效

**原因**: PageHelper 未正确配置。

**解决**:
1. 确认 Controller 中调用了 `startPage()`（来自 `BaseController`）
2. 确认 `application.yml` 中 PageHelper 配置：
   ```yaml
   pagehelper:
     helperDialect: mysql
     supportMethodsArguments: true
   ```
3. 分页调用必须在查询语句之前

#### Q: MyBatis 找不到 Mapper XML

**解决**:
1. 确认 `application.yml` 中 `mybatis.mapperLocations: classpath*:mapper/**/*Mapper.xml`
2. 确认 XML 文件在 `resources/mapper/` 下
3. 确认 XML 的 `namespace` 与 Mapper 接口全限定名一致

### 5.3 认证与权限问题

#### Q: 接口返回 401 未授权

**排查步骤**:
1. 检查请求 Header 是否携带 `Authorization: Bearer <token>`
2. 检查 Token 是否过期（默认 30 分钟）
3. 检查 Redis 中是否存在该 Token（Key 格式：`login_tokens:<uuid>`）
4. 查看日志中的 Token 校验失败原因

#### Q: 接口返回 403 权限不足

**排查步骤**:
1. 检查 Controller 方法上的 `@PreAuthorize` 注解的权限标识
2. 检查当前用户角色是否包含对应权限
3. 通过 `GET /getInfo` 查看用户拥有的 `permissions` 列表
4. 超级管理员（admin）拥有 `*:*:*` 权限，应能访问所有接口

#### Q: 数据权限不生效

**排查步骤**:
1. 检查 Service 方法是否标注 `@DataScope(deptAlias = "d", userAlias = "u")`
2. 检查 Mapper XML 中是否包含 `${params.dataScope}` 占位符
3. 检查角色的 `data_scope` 配置是否正确

XML 示例：
```xml
<select id="selectUserList" resultMap="SysUserResult">
    select u.*, d.dept_name
    from sys_user u
    left join sys_dept d on u.dept_id = d.dept_id
    where u.del_flag = '0'
    ${params.dataScope}
</select>
```

### 5.4 定时任务问题

#### Q: 定时任务不执行

**排查步骤**:
1. 检查 `sys_job` 表中任务状态 `status` 是否为 `0`（正常）
2. 检查 `invoke_target` 格式是否正确：`beanName.methodName('params')`
3. 检查 Bean 是否在 Spring 容器中（加 `@Component` 注解）
4. 查看 `sys_job_log` 中的异常信息
5. 检查 `misfire_policy` 策略配置

#### Q: 定时任务执行报错

**排查步骤**:
1. 查看 `sys_job_log.exception_info` 字段
2. 确保调用方法无参数时括号不能省略：`ryTask.ryParams()`（不是 `ryTask.ryParams`）
3. 确保参数类型与目标方法签名匹配

### 5.5 代码生成问题

#### Q: 代码生成导入表失败

**解决**:
1. 确认数据库中存在该表
2. 确认 `generator.yml` 中配置的包名正确
3. 检查 `gen_table` 表是否已有同名记录（需先删除再导入）

#### Q: 生成的代码不符合预期

**解决**:
1. 在代码生成页面编辑列配置，调整 Java 类型、查询方式、显示类型
2. 设置正确的模板类型（crud/tree/sub）
3. 预览确认无误后再下载

### 5.6 性能优化建议

| 场景 | 优化方案 |
|------|---------|
| 大表查询慢 | 使用 `@DataScope` 限制数据范围，合理建索引 |
| 日志写入慢 | 操作日志通过 `AsyncManager` 异步写入 |
| 频繁查询字典 | 使用 `DictUtils` 从 Redis 缓存读取 |
| 频繁查询参数 | 使用 `SysConfigService` 的缓存机制 |
| 接口响应慢 | 使用 `@RateLimiter` 限制高频接口 |
| 数据库连接池 | 调整 Druid 的 `maxActive`、`initialSize` 参数 |
| 前端列表慢 | 使用虚拟滚动、按需加载、分页大小优化 |
| 文件上传慢 | 调整 `spring.servlet.multipart.max-file-size` |

### 5.7 其他常见问题

#### Q: XSS 过滤器拦截了正常内容

**解决**: 在 `application.yml` 中配置排除路径：
```yaml
xss:
  enabled: true
  excludes: /system/notice/*
  urlPatterns: /system/*,/monitor/*,/tool/*
```

#### Q: 重复提交被拦截

**解决**:
1. 检查接口是否需要防重复提交（`@RepeatSubmit`）
2. 调整 `@RepeatSubmit(interval = 5000)` 的间隔时间
3. 确保请求 Header 中的 Token 一致

#### Q: 文件下载失败

**解决**:
1. 确认文件路径在 `application.yml` 的 `profile` 配置目录下
2. 检查 `CommonController.download` 的文件路径拼接逻辑
3. 确认文件存在且有读取权限
