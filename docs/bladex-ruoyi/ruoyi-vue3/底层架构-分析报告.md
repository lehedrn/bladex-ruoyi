> 分析版本：RuoYi 3.9.2（Spring Boot 4 + Spring Security 7 + Jakarta EE）
> 分析范围：ruoyi-common + ruoyi-framework

## 2. 框架入口点与启动机制

### 2.1 ApplicationConfig 全局注解配置

**文件路径**：`ruoyi-framework/.../config/ApplicationConfig.java`

```java
@Configuration
@EnableAspectJAutoProxy(exposeProxy = true)
@MapperScan("com.ruoyi.**.mapper")
public class ApplicationConfig {}
```

- `@EnableAspectJAutoProxy(exposeProxy = true)`：暴露 AOP 代理到 `AopContext`，允许方法内部通过 `AopContext.currentProxy()` 调用代理方法
- `@MapperScan("com.ruoyi.**.mapper")`：通配符扫描所有子模块的 Mapper 接口

### 2.2 配置类清单

**文件路径**：`ruoyi-framework/.../config/` 目录

| 配置类 | 作用 | 注册的 Bean |

| `MyBatisConfig` | MyBatis SqlSessionFactory | `SqlSessionFactory`（支持 `*` 通配符 typeAliasesPackage） |

## 3. 安全基础设施

### 3.1 Spring Security 过滤器链

**文件路径**：`ruoyi-framework/.../config/SecurityConfig.java`

```java
@EnableMethodSecurity(prePostEnabled = true, securedEnabled = true)
@Configuration
public class SecurityConfig {
    @Bean
    protected SecurityFilterChain filterChain(HttpSecurity httpSecurity) { ... }
}
```

**过滤器链顺序**（从外到内）：
1. `CorsFilter`（跨域，最早）
2. `RepeatableFilter`（可重复读请求体，FilterConfig 注册）
3. `XssFilter`（XSS 防护，FilterConfig 注册）
4. `JwtAuthenticationTokenFilter`（JWT 认证，在 `UsernamePasswordAuthenticationFilter` 之前）
5. `LogoutFilter`（登出处理）
6. Spring Security 内置过滤器

**安全策略**：
- CSRF 禁用（无状态 Token 架构）
- Session 策略：`STATELESS`（不创建 Session）
- 缓存控制：禁用 Cache-Control，frameOptions 设为 `sameOrigin`

**放行 URL**：
- 硬编码：`/login`, `/register`, `/captchaImage`
- 静态资源：`GET /*.html, /*.css, /*.js, /profile/**`
- 开发工具：`/swagger-ui.html`, `/v3/api-docs/**`, `/swagger-ui/**`, `/druid/**`
- 动态扫描：`PermitAllUrlProperties` 收集的 `@Anonymous` 注解 URL

### 3.2 JWT Token 处理

**文件路径**：`ruoyi-framework/.../web/service/TokenService.java`

**Token 架构**：JWT + Redis 双层验证

| 步骤 | 说明 |
|------|------|
| 生成 Token | 用 `UUID` 作为唯一标识，JWT 载荷中存放 `login_user_key=uuid` 和 `sub=username`，签名算法 `HS512` |
| 存储 Token | `LoginUser` 对象序列化后存入 Redis，key 为 `login_tokens:{uuid}`，过期时间由 `token.expireTime` 配置 |
| 验证 Token | 从请求头 `token.header` 提取 Token，解析 JWT 获取 uuid，再从 Redis 查询 `LoginUser` |
| 自动续期 | 距离过期不足 20 分钟时自动刷新 Redis 过期时间 |
| 删除 Token | 登出时从 Redis 删除 key |
| 权限刷新 | `refreshPermissionByRoleId()` 扫描所有在线用户，匹配角色后重新加载权限 |

**过滤器执行流程**：`ruoyi-framework/.../security/filter/JwtAuthenticationTokenFilter.java`

```
请求 -> 提取 Token -> 解析 JWT -> Redis 查询 LoginUser -> 创建 Authentication -> 放入 SecurityContext
```

### 3.3 认证流程

**文件路径**：`ruoyi-framework/.../web/service/SysLoginService.java`

```
login(username, password, code, uuid)
  ├── validateCaptcha()         // 验证码校验（Redis 中 captcha_codes:{uuid}）
  ├── loginPreCheck()           // 前置校验
  │     ├── 用户名/密码长度校验
  │     └── IP 黑名单校验（sys.login.blackIPList 配置）
  ├── AuthenticationManager.authenticate()  // 委托 Spring Security
  │     └── UserDetailsServiceImpl.loadUserByUsername()
  │           ├── 查询用户（ISysUserService）
  │           ├── 检查删除/停用状态
  │           ├── passwordService.validate()（密码验证+重试计数）
  │           └── permissionService.getMenuPermission()（加载权限）
  ├── AsyncManager.recordLogininfor()  // 异步记录登录日志
  └── tokenService.createToken()      // 生成 Token
```

### 3.4 密码服务

**文件路径**：`ruoyi-framework/.../web/service/SysPasswordService.java`

- 加密方式：`BCryptPasswordEncoder`
- 重试限制：Redis 记录失败次数 `pwd_err_cnt:{username}`
  - 超过 `user.password.maxRetryCount` 次后抛出 `UserPasswordRetryLimitExceedException`
  - 锁定时间由 `user.password.lockTime` 配置（分钟）
  - 成功后清除 Redis 计数

### 3.5 登录用户模型

**文件路径**：`ruoyi-common/.../core/domain/model/LoginUser.java`

实现 Spring Security 的 `UserDetails` 接口，核心字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| userId | Long | 用户 ID |
| deptId | Long | 部门 ID |
| token | String | 唯一标识（UUID） |
| loginTime | Long | 登录时间戳 |
| expireTime | Long | 过期时间戳 |
| ipaddr | String | 登录 IP |
| loginLocation | String | 登录地点 |
| browser/os | String | 浏览器/操作系统 |

### 3.6 权限服务

**文件路径**：`ruoyi-framework/.../web/service/PermissionService.java`

注册为 Bean 名 `"ss"`，供 SpEL 表达式使用（如 `@ss.hasPermi('system:user:list')`）：

| 方法 | 说明 |
|------|------|
| `hasPermi(permission)` | 检查是否具备某权限 |
| `lacksPermi(permission)` | 检查是否不具备某权限 |
| `hasAnyPermi(permissions)` | 检查是否具备任一权限（逗号分隔） |
| `hasRole(role)` | 检查是否具备某角色（admin 角色跳过检查） |
| `lacksRole(role)` | 检查是否不具备某角色 |
| `hasAnyRoles(roles)` | 检查是否具备任一角色 |

**文件路径**：`ruoyi-framework/.../web/service/SysPermissionService.java`

负责从数据库加载权限数据：
- `getMenuPermission(user)`：管理员返回 `*:*:*`，普通用户遍历角色聚合菜单权限
- `getRolePermission(user)`：返回角色 key 集合

### 3.7 @Anonymous 注解自动放行

**文件路径**：`ruoyi-common/.../annotation/Anonymous.java` + `ruoyi-framework/.../config/properties/PermitAllUrlProperties.java`

`PermitAllUrlProperties` 实现 `InitializingBean`，在 `afterPropertiesSet()` 中：
1. 从 `RequestMappingHandlerMapping` 获取所有 HandlerMethod
2. 扫描方法和类上的 `@Anonymous` 注解
3. 将路径中的 `{pathVar}` 替换为 `*`
4. 收集到 `urls` 列表供 `SecurityConfig` 使用

### 3.8 登出处理

**文件路径**：`ruoyi-framework/.../security/handle/LogoutSuccessHandlerImpl.java`

- 从请求中提取 `LoginUser`
- 调用 `tokenService.delLoginUser()` 删除 Redis 中的 Token
- 异步记录退出日志
- 返回 JSON 成功响应

### 3.9 认证失败入口

**文件路径**：`ruoyi-framework/.../security/handle/AuthenticationEntryPointImpl.java`

实现 `AuthenticationEntryPoint`，未认证时返回 HTTP 401 + JSON 错误信息。

## 5. AOP 切面与拦截器

### 5.1 切面执行顺序

| 切面 | Order | 通知类型 | 切入点 |
|------|-------|---------|--------|
| `DataSourceAspect` | 1（最高） | `@Around` | `@annotation(DataSource)` 或 `@within(DataSource)` |
| `DataScopeAspect` | 默认 | `@Before` | `@annotation(DataScope)` |
| `RateLimiterAspect` | 默认 | `@Before` | `@annotation(RateLimiter)` |
| `LogAspect` | 默认 | `@Before` + `@AfterReturning` + `@AfterThrowing` | `@annotation(Log)` |

### 5.2 DataSourceAspect 多数据源切换

**文件路径**：`ruoyi-framework/.../aspectj/DataSourceAspect.java`

```
方法调用
  └── @Around 拦截
       ├── 读取 @DataSource 注解（方法优先，其次类）
       ├── DynamicDataSourceContextHolder.setDataSourceType()
       ├── point.proceed() 执行业务方法
       └── finally: DynamicDataSourceContextHolder.clearDataSourceType()
```

### 5.3 DataScopeAspect 数据权限

**文件路径**：`ruoyi-framework/.../aspectj/DataScopeAspect.java`

**工作原理**：
1. 读取方法上的 `@DataScope` 注解获取表别名（deptAlias/userAlias）和字段名
2. 遍历当前用户的所有角色，根据角色的 `dataScope` 值拼接 SQL WHERE 条件：

| dataScope | 生成的 SQL 片段 |
|-----------|----------------|
| `1` 全部数据 | 空字符串（不限制） |
| `2` 自定义数据 | `OR dept_id IN (SELECT dept_id FROM sys_role_dept WHERE role_id = ?)` |
| `3` 本部门 | `OR dept_id = ?` |
| `4` 本部门及以下 | `OR dept_id IN (SELECT dept_id FROM sys_dept WHERE find_in_set(?, ancestors))` |
| `5` 仅本人 | `OR user_id = ?` |

3. 将拼接好的 SQL 放入 `BaseEntity.params.dataScope` 中，供 MyBatis XML 中的 `${dataScope}` 引用

**关键设计**：
- 超级管理员不执行过滤
- 先清空 `dataScope` 参数防止 SQL 注入
- 多个自定义数据权限角色时使用 `IN (...)` 避免多次拼接

### 5.4 RateLimiterAspect 限流

**文件路径**：`ruoyi-framework/.../aspectj/RateLimiterAspect.java`

- 使用 Redis Lua 脚本（`RedisConfig.limitScript`）实现计数器限流
- Key 格式：`{key_prefix}+{IP}(可选)+{类名}-{方法名}`
- `LimitType.DEFAULT`：全局计数
- `LimitType.IP`：按 IP 分别计数
- 超出限制时抛出 `ServiceException("访问过于频繁，请稍候再试")`

### 5.5 LogAspect 操作日志

**文件路径**：`ruoyi-framework/.../aspectj/LogAspect.java`

**三阶段通知**：
- `@Before`：记录开始时间（ThreadLocal）
- `@AfterReturning`：正常返回时记录日志
- `@AfterThrowing`：异常时记录错误信息

**记录内容**：操作人、IP、URL、部门、方法名、请求方式、请求参数、返回结果、耗时、业务类型、操作人类型、错误信息

**敏感数据过滤**：`password`, `oldPassword`, `newPassword`, `confirmPassword` 以及注解指定的 `excludeParamNames`

**异步写入**：通过 `AsyncManager.me().execute(AsyncFactory.recordOper(operLog))` 延迟 10ms 异步写入数据库

### 5.6 RepeatSubmitInterceptor 防重复提交

**文件路径**：
- 抽象类：`ruoyi-framework/.../interceptor/RepeatSubmitInterceptor.java`
- 实现类：`ruoyi-framework/.../interceptor/impl/SameUrlDataInterceptor.java`

**注册位置**：`ResourcesConfig.addInterceptors()` -> 拦截 `/**`

**SameUrlDataInterceptor 判断逻辑**：
1. 从请求体或 ParameterMap 获取请求参数
2. 缓存 key：`repeat_submit:{url}{token}`
3. 缓存 value：`{url: {repeatParams: 参数JSON, repeatTime: 时间戳}}`
4. 对比参数是否相同 + 时间间隔是否小于 `@RepeatSubmit.interval()`（默认 5000ms）
5. 判定为重复提交时直接返回 JSON 错误响应，不调用 Controller

## 7. Filter 链详解

### 7.1 Filter 注册顺序

**文件路径**：`ruoyi-framework/.../config/FilterConfig.java`

| Filter | Order | 条件 | 匹配路径 |
|--------|-------|------|---------|
| `XssFilter` | `HIGHEST_PRECEDENCE` | `xss.enabled=true` | 配置 `xss.urlPatterns` |
| `RefererFilter` | `HIGHEST_PRECEDENCE` | `referer.enabled=true` | `/profile/*` |
| `RepeatableFilter` | `LOWEST_PRECEDENCE` | 无条件 | `/*` |

**Spring Security 过滤器链**（在 SecurityConfig 中注册）：
1. `CorsFilter`（在 JWT Filter 和 LogoutFilter 之前）
2. `JwtAuthenticationTokenFilter`（在 `UsernamePasswordAuthenticationFilter` 之前）

**完整请求处理链路**：
```
RepeatableFilter（最低优先级，包装请求体）
  └── XssFilter（XSS 过滤，包装请求参数）
       └── RefererFilter（防盗链，/profile/*）
            └── CorsFilter（跨域）
                 └── Spring Security FilterChain
                      └── JwtAuthenticationTokenFilter（JWT 认证）
                           └── Controller
```

### 7.2 XssFilter XSS 防护

**文件路径**：`ruoyi-common/.../filter/XssFilter.java` + `XssHttpServletRequestWrapper.java`

- GET/DELETE 请求不过滤
- 配置的 exclude URLs 不过滤
- 使用 `XssHttpServletRequestWrapper` 包装请求：
  - `getParameterValues()`：对每个参数值调用 `EscapeUtil.clean()` + trim
  - `getInputStream()`：JSON 请求体也经过 XSS 清理

### 7.3 RepeatableFilter 可重复读

**文件路径**：`ruoyi-common/.../filter/RepeatableFilter.java` + `RepeatedlyRequestWrapper.java`

- 仅对 `Content-Type: application/json` 的请求包装
- `RepeatedlyRequestWrapper` 将请求体读入 `byte[]`，每次 `getInputStream()` 返回新的 `ByteArrayInputStream`
- 使 `@RequestBody` 和手动读取请求体可以共存

### 7.4 RefererFilter 防盗链

**文件路径**：`ruoyi-common/.../filter/RefererFilter.java`

- 检查 `Referer` 头是否包含 `allowedDomains` 中的域名
- 不匹配时返回 HTTP 403

## 13. 设计模式识别

### 13.1 模式清单

| 模式 | 应用点 | 说明 |
|------|--------|------|
| **策略模式** | `DynamicDataSource` | `AbstractRoutingDataSource.determineCurrentLookupKey()` 根据策略选择数据源 |
| **模板方法** | `RepeatSubmitInterceptor` | 抽象类定义流程，子类实现 `isRepeatSubmit()` |
| **工厂模式** | `AsyncFactory` | 静态工厂方法创建 `TimerTask` 实例 |
| **单例模式** | `AsyncManager` | 私有构造 + 静态 `me()` 方法 |
| **装饰器模式** | `XssHttpServletRequestWrapper`, `RepeatedlyRequestWrapper` | 包装 `HttpServletRequest` 增强行为 |
| **责任链模式** | Filter 链 + Security FilterChain | 多个 Filter 依次处理请求 |
| **代理模式** | AOP 切面 | Spring AOP 动态代理 |
| **观察者模式** | Spring 事件机制 | `InitializingBean` 回调收集 `@Anonymous` URL |
| **上下文模式** | `DynamicDataSourceContextHolder`, `AuthenticationContextHolder`, `PermissionContextHolder` | ThreadLocal/RequestAttributes 存储上下文 |
| **门面模式** | `SecurityUtils`, `DictUtils` | 统一入口简化复杂操作 |
| **Builder 模式** | `AjaxResult` 链式调用 | `put()` 返回 `this` |

### 13.2 架构特征总结

1. **无状态 Token 架构**：禁用 Session，JWT + Redis 双层验证，适合水平扩展
2. **多层过滤器**：Servlet Filter -> Spring Security Filter -> Spring Interceptor -> AOP Aspect
3. **异步日志写入**：所有日志操作通过 `AsyncManager` 异步执行，不阻塞业务请求
4. **注解驱动**：几乎所有基础设施能力（限流、日志、数据权限、防重复、数据源切换）都通过自定义注解 + AOP 实现
5. **Redis 深度集成**：Token 存储、验证码、限流、字典缓存、参数缓存、防重复提交全部使用 Redis
6. **数据权限体系**：基于角色的 5 级数据权限（全部/自定义/本部门/部门及以下/仅本人），通过 SQL 动态拼接实现
7. **安全纵深**：XSS 过滤 + Referer 防盗链 + JWT 认证 + BCrypt 密码加密 + 密码重试限制 + IP 黑名单 + 数据脱敏
