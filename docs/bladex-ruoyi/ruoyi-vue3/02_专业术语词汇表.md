## 1. 术语标准化

### 1.1 认证与授权

| 术语 | 英文 | 含义 | 代码来源 |
|------|------|------|----------|
| JWT Token | JSON Web Token | 基于签名的无状态认证令牌，存储 UUID 引用 | `TokenService.java` |
| LoginUser | Login User | 登录用户信息对象，实现 Spring Security 的 UserDetails 接口 | `ruoyi-common/.../domain/model/LoginUser.java` |
| BCrypt | BCrypt | 密码加密算法，用于存储和比对用户密码 | `SecurityUtils.java:100` |
| 认证 | Authentication | 验证用户身份（登录） | `SysLoginService.java` |
| 授权 | Authorization | 验证用户是否有权限执行操作 | `@PreAuthorize` 注解 |
| RBAC | Role-Based Access Control | 基于角色的访问控制模型 | 整个权限体系 |

| 术语 | 英文 | 含义 | 代码来源 |

### 1.3 数据范围（Data Scope 5 级模型）

| 级别 | 常量 | 含义 | SQL 效果 |
|------|------|------|----------|
| 1 | DATA_SCOPE_ALL | 全部数据权限 | 不添加过滤条件 |
| 2 | DATA_SCOPE_CUSTOM | 自定义数据权限 | `dept_id IN (SELECT dept_id FROM sys_role_dept WHERE role_id = ?)` |
| 3 | DATA_SCOPE_DEPT | 本部门数据权限 | `dept_id = 当前用户部门ID` |
| 4 | DATA_SCOPE_DEPT_AND_CHILD | 本部门及以下 | `dept_id IN (SELECT dept_id FROM sys_dept WHERE find_in_set(?, ancestors))` |
| 5 | DATA_SCOPE_SELF | 仅本人数据权限 | `user_id = 当前用户ID` |

来源：`Constants.java:177-202` / `DataScopeAspect.java`

## 2. 纠正对照表

| 常见误解 | 正确理解 | 说明 |
|----------|----------|------|
| "JWT 中存储了用户信息" | JWT 中只存储 UUID（login_user_key），用户信息在 Redis | `TokenService.java:115-150` |
| "Token 30分钟后过期" | 用户持续活跃时会自动续期（≤20分钟阈值），只有停止操作超30分钟才过期 | `TokenService.java:134` |
| "数据权限是数据库层面的" | 数据权限通过 AOP 在 Service 层动态注入 SQL 片段 | `DataScopeAspect.java` |
| "删除用户就是删数据库" | 使用软删除（delFlag='2'），查询时过滤 | `SysUserMapper.xml:217` |
| "菜单就是页面路由" | 菜单分 3 种类型：M(目录)、C(菜单)、F(按钮)，只有 M/C 生成路由 | `SysMenuServiceImpl.java` |
| "角色关联有外键约束" | 关联表无数据库外键，由应用层维护 | SQL DDL 中无 FOREIGN KEY |
| "部门 ancestors 是自动维护的" | 由 Service 层在增改时手动计算和批量更新 | `SysDeptServiceImpl.java:213-282` |
