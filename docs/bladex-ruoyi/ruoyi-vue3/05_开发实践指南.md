## 1. 设计模式应用

### 1.1 策略模式 — 数据范围过滤

**场景：** 不同角色的数据权限级别不同

```
DataScopeAspect (上下文)
  ├── DATA_SCOPE_ALL 策略 → 不添加过滤
  ├── DATA_SCOPE_CUSTOM 策略 → sys_role_dept 子查询
  ├── DATA_SCOPE_DEPT 策略 → 本部门匹配
  ├── DATA_SCOPE_DEPT_AND_CHILD 策略 → ancestors find_in_set
  └── DATA_SCOPE_SELF 策略 → user_id 匹配
```

**文件：** `DataScopeAspect.java` / `Constants.java:177-202`

### 1.2 模板方法模式 — 防重复提交

**场景：** 抽象拦截器定义流程骨架，具体实现由子类提供

```
RepeatSubmitInterceptor (抽象类)
  ├── preHandle() — 模板方法，定义检查流程
  └── isRepeatSubmit() — 抽象方法，由子类实现
        └── SameUrlDataInterceptor — 基于 URL+参数+Token 去重
```

**文件：** `RepeatSubmitInterceptor.java` / `SameUrlDataInterceptor.java`

### 1.3 工厂模式 — 异步任务工厂

**场景：** 创建不同类型的异步任务

```
AsyncFactory (工厂类)
  ├── recordLogininfor() — 创建登录日志记录任务
  └── recordOper() — 创建操作日志记录任务
```

**文件：** `AsyncManager.java` / `factory/AsyncFactory.java`

### 1.4 单例模式 — 异步管理器

```
AsyncManager.me() — 静态方法返回单例
  └── ScheduledExecutorService 线程池执行异步任务
```

**文件：** `AsyncManager.java`

### 1.5 责任链模式 — Spring Security 过滤器链

```
CorsFilter → JwtAuthenticationTokenFilter → authorizeHttpRequests → @PreAuthorize
```

每个过滤器独立处理请求，按链式传递。

**文件：** `SecurityConfig.java`

### 1.6 观察者模式 — 动态路由加载

```
后端返回菜单树 (事件源)
  ↓
permission store.generateRoutes() (监听者)
  ↓
router.addRoute() (更新路由注册)
  ↓
Sidebar 组件自动渲染新菜单 (视图更新)
```

**文件：** `permission.js` / `permission store`

## 2. 最佳实践

### 2.1 分页查询模式

```java
// Controller 层
public TableDataInfo list(SysUser user) {
    startPage();                        // PageHelper.startPage() 设置 ThreadLocal
    List<SysUser> list = userService.selectUserList(user);
    return getDataTable(list);          // 封装为 {code, msg, total, rows}
}
```

**关键点：**
- `startPage()` 必须在查询前调用，基于 ThreadLocal
- 如果有多个查询，需要再次调用 `startPage()`
- 记得在适当时候调用 `clearPage()` 避免影响后续查询

## 3. 常见陷阱

### 3.1 ⚠️ ThreadLocal 泄露

| 场景 | 风险 | 解决方案 |
|------|------|----------|
| PageHelper `startPage()` | 设置后如果后续代码抛异常，ThreadLocal 未清理 | 框架自动清理，但需注意 `clearPage()` |
| DynamicDataSource `setDataSourceType()` | 切换数据源后未清理 | `finally` 块中 `clearDataSourceType()` |
| AuthenticationContextHolder | ThreadLocal 存储认证 Token | 认证完成后 `clear()` |

### 3.2 ⚠️ 数据权限 SQL 注入

`${params.dataScope}` 使用 MyBatis 原始字符串拼接（非 `#{}` 参数化）。

**风险：** 如果 `dataScope` 值被恶意篡改，可能注入 SQL。
**防护：** `DataScopeAspect` 执行前先调用 `clearDataScope()` 清理已有值。

### 3.3 ⚠️ 角色变更时的在线用户权限刷新

```java
refreshPermissionByRoleId(roleId, permissionService)
  → RedisCache.keys(LOGIN_TOKEN_KEY + "*")  // 扫描所有在线 token
  → 遍历每个 LoginUser 重新计算权限
```

**风险：** 用户量大时（如 10000+ 在线用户），此操作会非常耗时且阻塞主线程。
**建议：** 生产环境可改为异步刷新或标记失效、等用户下次请求时自动刷新。

### 3.4 ⚠️ JWT Secret 硬编码

默认配置中 `token.secret = abcdefghijklmnopqrstuvwxyz` 是明文硬编码。

**风险：** 如果部署时不修改，攻击者可以伪造 JWT。
**建议：** 生产环境必须通过环境变量覆盖。

### 3.5 ⚠️ 密码错误信息泄露

当前登录失败时，返回的错误信息区分"用户不存在"和"密码错误"。

**风险：** 攻击者可通过错误信息枚举已注册用户。
**建议：** 统一返回"用户名或密码错误"。

### 3.6 ⚠️ 菜单名称重复

菜单名只在**同父级内**唯一，全局可以重名。

**影响：** 如果不同父级下有同名菜单，通过名称查找时可能返回错误结果。
**代码：** `SysMenuMapper.xml:133` — `WHERE menu_name = ? AND parent_id = ?`

## 4. 开发规范总结

### 4.1 Controller 层

- 继承 `BaseController` 获得分页和响应构建能力
- 使用 `@PreAuthorize` 进行方法级权限控制
- 使用 `@Log` 自动记录操作日志
- 返回值统一使用 `AjaxResult` 或 `TableDataInfo`

### 4.2 Service 层

- 接口命名 `ISysXxxService`，实现类 `SysXxxServiceImpl`
- 使用 `@DataScope` 注解触发数据权限过滤
- 多表操作使用 `@Transactional`
- 唯一性校验通过 Mapper 查询，不依赖数据库约束

### 4.3 前端开发

- CRUD 页面遵循标准模板：搜索表单 + 工具栏 + 表格 + 分页 + 对话框
- 使用 `useDict()` 加载字典数据，`DictTag` 组件渲染
- 按钮级权限使用 `v-hasPermi` 指令
- API 调用统一通过 `@/utils/request.js` 封装的 Axios 实例
