# 05 开发实践指南

> 本文档综合 RuoYi-Vue3 底层架构和后端分析报告中的设计模式、最佳实践、开发指南等内容。

---

## 1. 设计模式应用

### 1.1 后端设计模式

| 模式 | 应用点 | 说明 |
|------|--------|------|
| **策略模式** | DynamicDataSource | AbstractRoutingDataSource.determineCurrentLookupKey() 根据策略选择数据源 |
| **模板方法** | RepeatSubmitInterceptor | 抽象类定义流程，子类实现 isRepeatSubmit() |
| **工厂模式** | AsyncFactory | 静态工厂方法创建 TimerTask 实例 |
| **单例模式** | AsyncManager | 私有构造 + 静态 me() 方法 |
| **装饰器模式** | XssHttpServletRequestWrapper, RepeatedlyRequestWrapper | 包装 HttpServletRequest 增强行为 |
| **责任链模式** | Filter 链 + Security FilterChain | 多个 Filter 依次处理请求 |
| **代理模式** | AOP 切面 | Spring AOP 动态代理（DataSourceAspect/DataScopeAspect/RateLimiterAspect/LogAspect） |
| **观察者模式** | PermitAllUrlProperties | InitializingBean 回调收集 @Anonymous URL |
| **上下文模式** | DynamicDataSourceContextHolder, AuthenticationContextHolder | ThreadLocal/RequestAttributes 存储上下文 |
| **门面模式** | SecurityUtils, DictUtils | 统一入口简化复杂操作 |
| **Builder 模式** | AjaxResult | put() 返回 this，支持链式调用 |
| **Read-through Cache** | SysConfigServiceImpl, SysDictTypeServiceImpl | @PostConstruct 加载缓存，修改时同步更新 |

### 1.2 前端设计模式

| 模式 | 应用点 | 说明 |
|------|--------|------|
| **组件化** | 全局注册通用组件 | main.js 中 app.component() 注册，模板中直接使用 |
| **布局分层** | Layout → Views → Components | 骨架与内容分离，AppMain 负责 keep-alive |
| **CRUD 标准模板** | 所有管理页面 | 查询表单 + 操作按钮行 + el-table + Pagination + el-dialog |
| **状态管理** | Pinia Composition API | defineStore + setup 语法 |
| **权限控制三层** | 路由级/菜单级/按钮级 | 后端返回 → 前端过滤 → 指令控制 |

## 2. 最佳实践

### 2.1 后端最佳实践

| 实践 | 说明 | 示例 |
|------|------|------|
| 注解驱动开发 | 所有基础设施通过注解 + AOP 实现 | @Log/@DataScope/@RateLimiter/@RepeatSubmit |
| 统一响应格式 | 所有接口返回 AjaxResult | success()/error()/warn() 工厂方法 |
| 统一异常处理 | @RestControllerAdvice 集中处理 | GlobalExceptionHandler |
| 异步日志写入 | 不阻塞业务请求 | AsyncManager + AsyncFactory |
| 事务边界控制 | @Transactional 标注在 Service 方法 | 用户增删改（同时操作多表） |
| Redis 白名单防护 | 防反序列化攻击 | FastJson2JsonRedisSerializer AUTO_TYPE |
| 敏感数据过滤 | 日志记录时自动过滤密码 | LogAspect excludeParamNames |
| 数据脱敏 | @Sensitive 注解 + 非管理员脱敏 | 手机号/邮箱/身份证号等 |
| 接口限流 | @RateLimiter 注解 + Redis Lua 脚本 | 支持全局/IP 两种策略 |
| 防重复提交 | 前端 Axios + 后端拦截器双层防护 | sessionStorage 指纹 + Redis 标记 |

### 2.2 前端最佳实践

| 实践 | 说明 | 示例 |
|------|------|------|
| 统一 HTTP 封装 | Axios 拦截器处理 Token/错误 | request.js |
| 全局错误处理 | 响应拦截器按 code 分类处理 | 401/500/601/网络错误 |
| 动态路由加载 | import.meta.glob 预加载组件 | permission.js loadView() |
| 字典缓存 | dictStore 延迟加载 + 内存缓存 | useDict() |
| 页签持久化 | localStorage 可选开关 | tagsViewPersist |
| 主题样式 | CSS v-bind() + 动态计算 | Sidebar 组件主题 |
| 页面刷新机制 | redirect 路由 + keep-alive 清除 | $tab.refreshPage() |

## 3. 常见陷阱

### 3.1 数据权限陷阱

| 陷阱 | 说明 | 规避方法 |
|------|------|----------|
| 忘记写 @DataScope | Service 方法不标注注解，不会自动拼接 SQL | 需要数据权限的方法必须显式标注 |
| 别名不匹配 | MyBatis XML 中的表别名与 @DataScope 不一致 | 确保 XML 中使用的别名与注解参数一致 |
| SQL 注入风险 | params.dataScope 被恶意注入 | DataScopeAspect 先清空 dataScope 参数 |
| 超级管理员无限制 | roleId=1 的用户不执行数据权限过滤 | 测试时使用普通用户验证 |

### 3.2 Token 陷阱

| 陷阱 | 说明 | 规避方法 |
|------|------|----------|
| Token 续期不生效 | Redis key 被提前删除 | 不要在业务代码中手动操作 login_tokens 前缀的 key |
| 权限变更后旧 Token 仍有效 | TokenService.refreshPermissionByRoleId() 只扫描在线用户 | 修改角色权限后，离线用户下次请求时自动更新 |
| 多端登录冲突 | 同一账号多端登录，后者覆盖前者 | 框架未限制，需自行实现单点登录 |
| JWT 仅做签名验证 | JWT 中不包含用户权限信息 | 权限数据完全依赖 Redis，Redis 宕机会导致认证失败 |

### 3.3 事务陷阱

| 陷阱 | 说明 | 规避方法 |
|------|------|----------|
| 同类内部调用不走代理 | 同一 Service 中方法 A 调用方法 B，B 的 @Transactional 不生效 | 通过 AopContext.currentProxy() 调用 |
| 异常被吞掉 | catch 后不抛出，事务不回滚 | catch 块中必须 throw 或 TransactionAspectSupport |
| 多数据源事务 | 主从切换 + 事务可能不一致 | 写操作确保在 master 数据源 |

### 3.4 前端陷阱

| 陷阱 | 说明 | 规避方法 |
|------|------|----------|
| keep-alive 缓存不刷新 | 修改数据后返回列表页，数据是旧的 | 使用 $tab.refreshPage() 或 activated() 钩子 |
| 权限按钮不显示 | v-hasPermi 权限标识与后端不一致 | 核对后端 @PreAuthorize 中的权限标识 |
| 路由刷新后 404 | 页面刷新后动态路由未重新注册 | permission.js 守卫会自动重新获取 |
| 字典数据未更新 | 后端修改字典后前端缓存未刷新 | 需手动刷新页面或重新调用 useDict() |
| 防重复提交误拦截 | 相同接口连续请求被拦截 | 设置 config.headers.repeatSubmit = false |

## 4. 权限开发指南

### 4.1 后端权限开发

#### 4.1.1 接口权限

在 Controller 方法上添加 @PreAuthorize 注解：

```java
@PreAuthorize("@ss.hasPermi('system:user:add')")
@PostMapping
public AjaxResult add(@Validated @RequestBody SysUser user) {
    return toAjax(userService.insertUser(user));
}
```

**权限标识规范：** `模块:功能:操作`
- 模块：system/monitor/tool 等
- 功能：user/role/menu/dept/config/dict 等
- 操作：list/query/add/edit/remove/export/import/resetPwd 等

#### 4.1.2 匿名接口

使用 @Anonymous 注解自动放行：

```java
@Anonymous
@PostMapping("/register")
public AjaxResult register(@RequestBody RegisterBody registerBody) {
    return success(registerService.register(registerBody));
}
```

**注意：** 类上标注 @Anonymous 则类下所有方法均匿名访问。

#### 4.1.3 数据权限

在 Service 方法上添加 @DataScope 注解：

```java
@DataScope(deptAlias = "d", userAlias = "u")
public List<SysUser> selectUserList(SysUser user) {
    return userMapper.selectUserList(user);
}
```

**MyBatis XML 配合：**
```xml
<select id="selectUserList" resultType="SysUser">
    select u.* from sys_user u
    left join sys_dept d on u.dept_id = d.dept_id
    where u.del_flag = '0'
    ${params.dataScope}
</select>
```

### 4.2 前端权限开发

#### 4.2.1 按钮权限

使用 v-hasPermi 指令：

```html
<el-button v-hasPermi="['system:user:add']" @click="handleAdd">新增</el-button>
```

**多个权限（满足任一即可）：**
```html
<el-button v-hasPermi="['system:user:edit', 'system:user:add']">操作</el-button>
```

#### 4.2.2 角色控制

使用 v-hasRole 指令：

```html
<el-button v-hasRole="['admin']">管理员操作</el-button>
```

#### 4.2.3 编程式权限

使用 $auth 插件：

```js
if (this.$auth.hasPermi('system:user:export')) {
    // 有导出权限，显示导出按钮
}
```

#### 4.2.4 路由权限

动态路由定义 permissions 属性：

```js
{
  path: '/system/user-auth',
  permissions: ['system:user:edit'],
  children: [...]
}
```

框架自动在 permission.js 中过滤，无权限的路由不注册。

## 5. 数据权限使用指南

### 5.1 数据权限类型

| 类型 | 值 | 适用场景 |
|------|----|---------|
| 全部数据 | 1 | 系统管理员 |
| 自定义数据 | 2 | 需要精确控制部门的场景 |
| 本部门数据 | 3 | 部门经理只看本部门 |
| 本部门及以下 | 4 | 部门经理看下级部门 |
| 仅本人数据 | 5 | 普通员工只看自己数据 |

### 5.2 配置步骤

**步骤 1：** 在角色管理中设置角色的数据范围

**步骤 2：** 类型 2（自定义数据）需要在角色-部门树中勾选部门

**步骤 3：** Service 方法标注 @DataScope

```java
@DataScope(deptAlias = "d", userAlias = "u")
public List<SysXxx> selectXxxList(XxxQuery query) {
    return xxxMapper.selectXxxList(query);
}
```

**步骤 4：** MyBatis XML 中添加过滤条件

```xml
${params.dataScope}
```

### 5.3 注意事项

- `params.dataScope` 必须使用 `${}` 而非 `#{}`（因为是 SQL 片段）
- 表别名必须与 @DataScope 注解中的参数一致
- 超级管理员不受数据权限限制
- 多角色时取并集（多个角色的 dataScope 拼接为 OR 条件）

## 6. 接口开发规范

### 6.1 Controller 层规范

| 规范 | 说明 |
|------|------|
| 继承 BaseController | 提供 toAjax()、startPage()、getDataTable() 等通用方法 |
| 使用 @RestController + @RequestMapping | 定义路径前缀 |
| 每个方法标注 @Log | 记录操作日志 |
| 每个方法标注 @PreAuthorize | 控制访问权限 |
| 查询参数使用 GET | 分页查询使用 @GetMapping |
| 新增/修改使用 POST/PUT | 请求体使用 @RequestBody |
| 删除使用 @DeleteMapping | 路径参数使用 @PathVariable |
| 导出使用 @PostMapping | 通过 $download 通用下载方法 |

### 6.2 Service 层规范

| 规范 | 说明 |
|------|------|
| 定义接口（IXxxService） | 不直接暴露实现类 |
| 实现类标注 @Service | Spring 自动扫描 |
| 多表操作标注 @Transactional | 确保事务一致性 |
| 数据权限标注 @DataScope | 自动 SQL 过滤 |
| 唯一性校验在 Service 中 | checkXxxUnique() 方法 |
| 业务异常抛 ServiceException | 携带 code 和 message |

### 6.3 Mapper 层规范

| 规范 | 说明 |
|------|------|
| 接口标注 @Mapper | MyBatis 扫描 |
| XML 文件放在 mapper 目录 | classpath*:mapper/**/*Mapper.xml |
| SQL 使用 ${params.dataScope} | 数据权限过滤点 |
| 分页使用 PageHelper | startPage() 方法 |

### 6.4 前端 API 开发规范

| 规范 | 说明 |
|------|------|
| 放在 src/api/ 对应模块下 | 按业务域分类 |
| 每个函数返回 Promise | 使用 request 实例 |
| 路径与后端一致 | 核对接口契约文档 |
| GET 参数自动序列化 | request.js 拦截器处理 |
| 下载通过 $download 插件 | 不直接调用 axios |

### 6.5 前端页面开发规范

| 规范 | 说明 |
|------|------|
| 使用 <script setup> 语法 | Composition API |
| 定义 name 属性 | keep-alive 缓存需要 |
| 注入字典使用 useDict() | 统一缓存机制 |
| 表单校验使用 rules 对象 | Element Plus 表单验证 |
| 操作按钮带 v-hasPermi | 权限控制 |
| 分页使用 Pagination 组件 | 统一样式 |
| 表格使用 RightToolbar | 列显隐/搜索开关 |
